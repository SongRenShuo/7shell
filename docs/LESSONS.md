## 导入条目（2026-11-17 建账，源仓 2026-09~11 实战）

### 排障与取证

**I1 排障先挖根因链，别信表层包装的异常**
`unwrap_or_default`/`runCatching`/`catch` 吞掉后会留下 `None` 调用链假象。逐层 `.source()`（Rust）/`Caused by:`（Java）找根因；把「包装异常： null」当异常本身去修是反例。（源仓 L1）

**I2 判「搜不到/没有」之前先跑对照查询，证明搜索接口本身是好的**
每个「0」旁边并排给出同接口的已知非零查询读数；源本身不可用时把结论降级为「未取到」并写明原因。「搜了一遍没有」不区分「接口坏了/被限流」与「确实不存在」。（源仓 L14）

**I3 注释里点名的守卫必须真的存在**
在注释里断言「已由某某守卫保证」，先 `grep` 确认那个守卫类/测试在场，并写清适用版本；没落测试的「已合规」从未被机器验过。（源仓 L16）

**I4 CI 腿「绿」却不产出逐例口径就是空绿**
凡带「环境不满足就打印 + return」这类显式绿跳的腿，必须在同一 job 内产出一行逐例汇总（files/tests/skipped/failures）。没有这行数字，`exit 0` 什么都不证明。判定顺序固定：腿红先读环境，腿绿先读逐例口径。（源仓 L42）

**I5 构建静默死亡先读崩溃日志与内存提交量，别先怀疑代码或增量缓存**
「跑到某个 task 就结束、无编译错误也无 FAILED」按进程级死因排查：找当天崩溃日志（`hs_err_pid*.log` / Rust panic 落盘）→ 看内存提交量（commit）不是 CPU → 列本机构建进程的启动日期清孤儿。88% commit 的状态下继续叠构建+测试必然再崩。（源仓 L75）

**I6 判「用户手上那个包有没有这条修复」看产物字节，别信版本号**
扫安装目录里的类/符号或以行为差异为准。版本号没人动就仍是旧号，「版本号没变」与「代码是旧的」是两件事；每次给包必须同时给 sha256 与「装完确认文件修改时间」的自查方法。（源仓 L35）

### 验证纪律

**I7 反向验证的夹具要先算清「修复点之前还有几道闸门」**
撤掉修复看是否变红之前，夹具的每个参数都要过一遍沿途其它闸门——缺陷那道门之前若有更早的短路（家族排除、启发式、开关），夹具被截走就红不起来。判定办法：加临时探针打印被测链的实际产出，先证明夹具抵达目标层。夹具值还必须与守卫默认值拉开，两值撞车等于 0 红假绿。（源仓 L80 + L2）

**I8 反向验证前先提交；摘除探针后 grep 自证生效**
`git checkout -- <file>` 回退的是整个文件，同文件里未提交改动一起消失——摘之前先提交或只用编辑工具改回。摘除式探针最阴的失败是「探针没落地」：改完立刻 `grep -c` 确认目标语句真的不再执行。（源仓 L32 + L50）

**I9 同回合内改被测文件 ⇒ 已跑的门禁读数作废，必须复跑**
读数落地后冻结被测面；确要再改，重跑该面定向并更新读数。「顺手改一下，读数应该还绿」是反例。（源仓 L5）

**I10 时序类判据断言「调度值」，不要断言墙钟间隔比值**
拿时间差值当判据会把一次性预热成本算进第一段，在慢 runner 上必红。给被测对象加睡眠注入缝（生产注入真实睡眠、测试注入记录器），断言「被请求睡多久」的序列——与机器快慢完全无关且更强。（源仓 L18）

**I11 夹具钉定值必须指向「CI 克隆的那个远端」可达的提交**
钉定值只在已 push 到 CI 拉取的那个远端时才成立。改钉定值前跑 `git ls-remote` + `merge-base --is-ancestor` 两条只读判据；「本地能跑」恰恰因为对象躺在本机克隆里，与远端无关。（源仓 L19）

### 缓存与数据

**I12 校验判据必须对齐真正消费方的解析器与类型**
判「这份 JSON/配置能不能被加载」，要按真正消费它的那个解析器与类型约束去校验，不是「能否解析成通用树」。宽松解析器会放过裸值，严格消费者会拒绝——判据不一致的后果是「真机损坏形态被判成健康，自愈逻辑全程空转」。（源仓 L61）

**I13 「TTL 内一律命中」是伪缓存：命中条件里时间判据不能覆盖内容判据**
`TTL 内直接命中 || 内容未变` 的实际语义是「TTL 内无视内容」，同时吃掉「改了不生效」与「同键不同内容串味」。要吸收重建造成的伪失效，用内容型指纹（文本哈希），指纹代价必须远低于被缓存的那次计算。（源仓 L67）

**I14 抗抖动正缓存必须带收回条件，且收回判据只有一个合法来源——「查询成功且确认不存在」**
「返回值是否为空」不能当判据：它既可能是「确定没有」也可能是「这次没算完」。内部实现显式化三态 `Found / Absent / Unknown`（Found 入缓存 / Unknown 保留 / Absent 才收回），取消与错误永远算「没算完」。（源仓 L76）

**I15 按名字找目标先锚定身份域，禁无语义背书的宽松尾缀匹配**
先确定名字的身份域（命名空间/模块/包），判定只在该域内精确比较；「任意前缀 + 同名尾段」在单命名空间样例里看似无害，在多命名空间语料里把同名另一条认成同一条。放宽匹配必须能说出引擎侧的等价语义。测试夹具要主动造「多命名空间 + 同名」形态——单命名空间语料永远测不出这类错。（源仓 L79）

**I16 收窄「怎么认一个对象」的契约前，先枚举仓里既有实现暴露的形态**
只认一个方法名/字段名会把合法条目静默判成「无名」，症状不是报错而是「集合被滤空 → 上游永远收不到结果」。取名/取键这类兼容面一律走候选链，全都取不到才算缺席；「多候选就弃权」的保守降级，先用一条命令量真实数据的歧义度——歧义在真实项目里是常态时，「弃权」等于能力从不生效。（源仓 L41 + L36）

**I17 一次性元数据随载体走（消息/返回值/回调参数），别走共享可变状态**
跨线程、跨渲染次数传递的小块元数据（失败成因、诊断快照）优先编码进载体本身。只要还留一处「谁清谁写」的约定，就会被重复渲染、并发写方打掉；读方不清空，由下一次写入覆盖。（源仓 L40）

### 协作与提交

**I18 提交信息写 UTF-8 文件 `git commit -F`，禁内联反引号**
Git Bash 里 `commit -m` 的反引号被命令替换吃掉——报错但提交仍成功、信息静默缺段；`python -c` 双引号串同根更隐蔽。中文一律写文件传递，Bash 命令行直传必乱码；编辑后必回读校验关键内容在场。（源仓 L4）

**I19 跨调用改文件一律用编辑工具，Bash 内 python/heredoc 写文件可能不落盘**
沙盒拦截下同进程回读成功、跨调用丢失。Bash 内 python 只做只读分析。（源仓 L4）

**I20 每笔提交至少过编译——未编译提交堵死下游车道验证**
多车道共用主干时，一笔编译不过的提交让所有下游车道无法验证。提交前跑一次增量检查（`cargo check` / `pnpm typecheck`，秒级）；「我的改动是纯新增文件，编译肯定没问题」是反例。（源仓 L11）

**I21 修一个点要横向审计同型兄弟，机制替换要覆盖同形态的平行实现**
修一处缺陷时 grep 同模式调用点/同形状守卫/同谓词分支，本次一并修或明确登记。机制替换（全量扫描→索引、同步→异步、吞错→上抛）落笔前先把「同形态的弟弟们」列全——报障往往下一次落在没被点到的那条平行链上，时间差几天，容易被当成新 bug 从头再查。（源仓 S7 + L74）

**I22 修「某条信息没显示」之前，先枚举这个回调的全部消费点是否都接上了**
不许只改复现时走的那条调用链——先数同一个回调在文件里有几个调用点，逐个核对。看到「同一功能两个入口，只有其中一个正常」，先 diff 两个入口的接线，不要先怀疑数据或竞态。（源仓 L39）

**I23 共用工作树里别家车道的在途文档别用 `git stash push` 挪开**
stash 把文件在工作树里回到 HEAD 版本，对方下一次提交会把 pop 出来的冲突标记当成正常内容提交进主干。正路：等对方提交完再动；或 `git apply --cached` 只暂存自己那段。（源仓 L77）

**I24 本机 Windows 红线合集**
① Git Bash 调带 `/X` 参数的 Windows 工具会被 MSYS 转成路径（robocopy `/E` → `E:/`），一律写 `.ps1` 用 PowerShell 执行，robocopy 退出码 0~7 均为成功；② 无 BOM 的 UTF-8 `.ps1` 里的中文串会被 PowerShell 5.1 按 ANSI 读成乱码语法错——含中文一律用 pwsh 7 或文案纯 ASCII；③ 中文请求体写 UTF-8 文件再 `curl --data-binary`；④ 推送脚本仓名写死、回显目标 URL，别读凭据文件里的 `repo` 字段拼 URL（常是从别的仓拷来的旧值）。（源仓 L4/L6/L13/L47）

**I25 多组并行部署/运维：冲突由主控统一处置，判据落在磁盘字节与实连**
主控把「作业基准」写成共享文件（唯一事实源），凭据只放权限 600 的文件；组间抢资源/孤儿进程由主控读证据后统一清、定错峰顺序，不叫子代理自己 kill。环境会替换显示串时，别拿显示串改脚本，用逐字节比对或实连自证；别在任务运行中改脚本——在途进程会读到中间态。（源仓 L56）

### 流程与发布

**I26 UI/交互争议方案先给用户看形态，绿灯读数不构成方向依据**
形态预览/对照稿先行，用户点头再落码。定向全绿 → 落码 → 等真机反馈 → 整案撤除是反例（源仓两轮返工均此形态）；「预览点头」也不能替代「按原版逐项核对」。（源仓 L12）

**I27 后台长命令禁用 `2>&1 | tail -N` 收尾——失败正文会被截断吞掉，退出码还会被换成管道末命令的**
重定向全量到文件 + 紧跟 `echo "EXIT=$?"` 把真退出码打进日志，判读用 grep 提取。tail 要等上游 EOF 才输出，中途读输出文件恒为空，还会误判任务没起来。（源仓 L22）

**I28 CI 需要外部实例时，先问「它能不能由 runner 自给」**
共享实例会把「别人的机器挂了」变成「我们的门禁红了」，且一个连不上的库能生出十几条业务断言失败，读报的人只看到最后一条。能自给就自给（本仓 `deploy/lab/` 即此思路的落地）；确实不能自给的腿，在记录里显式写「环境腿、只能环境侧修」。（源仓 L43）

**I29 运维/部署脚本只放服务器＝没备份；口令只放服务器＝备份永久失效**
凡是要靠「机器重装后照单重建」的东西，事实源必须在仓库里，服务器上的副本只是部署产物。备份仓库口令必须离线双份（密码管理器或另一台设备各一份）——AK/SK 丢了还能新建，仓库口令丢了没有任何恢复路径。（源仓 L52）

**I30 CI 提速先量「全局地板」再动刀：单腿变快≠整轮变快**
动编排前先拉逐 job/逐 step 的起止时间找整轮关键路径与真地板；任何改动用同 workflow、只差一个变量的 A/B 轮验证，对比「整轮结束时刻」。已证伪路线：把最长腿切片并行（固定成本占大头）、把大对象预置进共享缓存（放大条目让所有腿的恢复一起变慢）。负收益立即 revert。（源仓 L72）

**I31 retry 救不了「一次性读完」的下载：先确认有没有续传语义**
一次 `read()` 拉大文件没有续传——每轮重试把同一个失败从头再演。正解：`Range` 从本地已落字节续拉 + 判据用服务端声明的 digest；连续 N 轮零进展即判链路不可用并把替代通道写进报错。`watch` 类命令的退出码不能当结论，判据取查询接口的最终状态。（源仓 L51）

### 工具与环境（第二批导入）

**I32 `git add -f` 对被忽略目录下的文件静默无效**
exit 0 无报错但暂存区是空的。绕过配方＝`git hash-object -w <file>` + `git update-index --add --cacheinfo 100644,<hash>,<path>`；提交后必回读 `git ls-files` 确认关键文件在场。（源仓 pitfall-git-add-force-silent-noop-ignored-dir）

**I33 本机 Git Bash 的 `grep` 是 ugrep 包装，`-c` 与管道会静默返空**
0 命中先怀疑工具。同族：`unzip … | grep -q` 假阴性（管道末命令退出码）、`comm` 对含中文/CRLF 清单恒给「零交集」（集合运算改 `grep -F`）、python 不认 `/f/` 路径、`sed -i` 会改行尾、cygpath 转分号分隔清单整串当一个路径。（源仓 pitfall-gitbash-grep-is-ugrep-wrapper / gitbash-toolchain-path-quirks）

**I34 超长单行表格行不能用「行首前缀」做编辑锚点**
`old_string` 只截行首会把原行残余粘到新行尾；`git diff --stat` 对单行文件恒显示 1 insertion，看不出被改坏。必须整行回读校验关键内容在场。（源仓 pitfall-single-line-table-edit-prefix-match）

**I44 提交身份先核 `user.email`——错邮箱把贡献归到别人账号**
提交邮箱抄了上游作者或模板值，Gitee/GitHub 的贡献图归到陌生账号；判据看 commits API 的 `author.login`。仓内写死 user.email，发现后 `--reset-author` 修正。（源仓 pitfall-commit-identity-wrong-email-owns-attribution）

### 构建与发行

**I35 发行物必须在干净树上构建——在途未提交改动会被编进包里**
`inspect`/自检类脚本只验版本与文案，验不出源码状态；跑门禁时树上有别人的在途改动，门禁 PASS 的包也不可发行。打包前 `git status` 无源码改动；实施代理报告须回答「跑门禁时树是否干净」。（源仓 pitfall-buildplugin-zip-tainted-by-inflight-changes）

**I36 嵌了构建时间戳的产物，哈希永不同——哈希不能作「同一份产物」的判据**
每次构建都唯一的字段（时间戳/随机 salt）让本地包与 CI 包必不同哈希；判内容一致用可复现锚点（版本、字节内标记），别拿哈希相等下「不是同一份」的结论。（源仓 pitfall-mpv-build-timestamp-vs-ci-zip-hash）

### 缓存与重试

**I37 「就绪 → 重算」的闭环可能自激：补不到结果也回调 ⇒ 几秒内多轮重算**
任何「就绪→重算」闭环都要问一句重算会不会再次触发等待。后台补齐的回调，无论成功失败都要有终止条件——同 key 同缓存代只补一次（缓存失效/调度失败才退回）。（源仓 pitfall-m2-warm-retry-self-exciting-loop）

**I38 预取要有失败记忆；首开慢先分清冷启动固定成本与算法成本**
解析不到又不写缓存时，每次重绘都会重触发预取，形成自旋。给失败结果也写记忆（带短 TTL）；收窄检索范围反而更慢时，先怀疑是冷索引/JIT 这类一次性固定成本——该挪走不该压。（源仓 pitfall-prefetch-needs-failure-memo-and-coldstart-vs-algorithm）

**I42 结果级 memo 必须挂在清单缓存槽自身；负缓存须哨兵**
memo 挂旁路槽时，旁路命中会跳过下层 TTL/有效性检查，形成「永远不失效」的第二层缓存。负缓存（「查过没有」）不能存 null（并发 Map 不收），用哨兵对象。（源仓 pitfall-cache-memo-shares-listing-slot）

### 验证与归因

**I39 性能归因先分段切再下结论；冷启动固定成本别算到算法头上**
把链路按段埋点（请求→计算→装配→呈现），逐段对时找断点。首次操作慢常是冷启动编译/索引这类固定成本（同一条第二次就是毫秒级），拿「刚打开第一次点」判算法慢会误判。（源仓 pitfall-preview-open-stage-split）

**I40 测试唯一键禁用时钟尾巴拼接**
时钟末几位取值空间小（如毫秒末 3 位只有千级），批量造数必撞键。唯一键一律原子序号或 UUID。（源仓 pitfall-test-unique-data-by-clock-tail）

**I41 别急着判「环境受限未验证」，先证明路径真的走不通**
归因环境之前先做对照：同样输入在最小复现里走不走得通。「环境问题」与「我的判据写错了」在表象上一样。（源仓 pitfall-blame-environment-before-proving-path）

**I43 耗时阈值类断言在慢 runner 上稳定假红**
「持续 N 秒」「首次完成不超过 N ms」这类判据把机器速度写进了断言——6 核本地一直绿、2 核 CI 稳定红。判据要么断行为（该不该发生），要么注入时钟缝断调度值（见 I10）。（源仓 pitfall-ci-slow-runner-amplifies-time-threshold-tests）

## 活跃规则

（本仓新产生的教训按时间追加在这里，编号从 A1 起；Seen 满 3 升级进规范并在此留指针。）

**A1 空集合省略是线格式的常态，前端镜像必须按「可能不在」写**
Rust 侧 `skip_serializing_if = "Vec::is_empty"` 让空数组不上线，TS 镜像写成必填后，消费端 `for…of` 直接抛 `not iterable`；Vue 把出错的子树卸掉，界面上表现为「整块面板消失」，控制台才是唯一线索。契约镜像的可选性要跟 `skip_serializing_if` 一一对应，夹具用**真实会发的形状**（叶子不带键）而不是手写的完整形状。证据：7shell `73eb01c`（磁盘分区叶子），真机点击即塌，单测全绿因为夹具虚构了 `children: []`。Seen 1。

**A2 可选链只保护到它左边那一层：`a?.b.length` 在 `b` 缺失时照样抛**
`overview?.crontab.length` 只对 `overview` 短路，`crontab` 缺席时仍然读 `undefined.length`；渲染期抛错被 Vue 吞掉并卸载子树，界面上是「切分区面板整块消失」，控制台里也只有一条 console.error。凡线格式里可能缺席的字段，访问其内部属性前再写一个 `?.`（`overview?.crontab?.length`），并用**旧宿主形状**（缺这些字段的应答）做回归用例——新字段的夹具永远是齐的，所以它证不了这条。证据：7shell `da580d1`，运行中的浏览器宿主比前端旧，切到「定时任务/登录记录」两分区即崩。Seen 1。
