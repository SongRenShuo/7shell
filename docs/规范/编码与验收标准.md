# 编码与验收标准

> 本文件机制导入自 mybatis-plus-sql-visualizer 仓的《编码与验收标准》（其条目全部来自教训账本 Seen 满 3 个不同日期的复发教训，另有显式标注来源的「机制导入」节）。
> 格式两列：左列一句话祈使句规则，右列「审查者/复核者具体看什么」。审查定向测试报告、复核收口读数、评审他人提交时逐条对照；不满足的条目要在报告里点名说哪条不满足。
> 演进规则：V/C 条目只能从 [`LESSONS.md`](../LESSONS.md) 升级进来（Seen ≥ 3），不允许直接在本文件立新规；M 条目只允许整节机制导入（须标注来源）。

## 验证与测试

| 规则 | 复核者看什么 |
|---|---|
| **V1 反向验证必须成对且有对照，空绿不算数** | 守卫/扫描类改动：摘掉修复分支必须变红（贴两次读数）；合成样本只证「规则看得见我造的形态」，须补真实形态对照；「全仓 0 违规」在写命中为 0 时是空绿；探针夹具值必须与守卫默认值拉开。 |
| **V2 定向测试以判据数收读数** | 报告必须给每类用例数（`cargo test` 的 `N passed` / vitest 的 tests 数），判据数对不上即视为没跑；过滤器不匹配会静默跑 0 个测试且退出码正常——看到 `0 passed` 就当没跑。改共享类型/守卫脚本后跑整桶而非单文件。 |
| **V3 收口多步禁用 `&&` 串联** | 多步收口用分号或显式检查每步退出码；合并/门禁的失败会伪装成「进行中」（源仓实测白等半小时）。 |
| **V4 工作树所有权与并发写隔离** | 接手掉线代理先 `git status` + 搜临时探针/RED PROBE 注释，确认工作树没停在「先红」中间态；并发车道禁同改 `src/`；**提交后 `git show --stat HEAD` 必须只列自己的文件**，读数贴进报告；跑长构建前过 `parallel_tasks.py check` + 登记。 |
| **V5 证据看产物，不看文档自述** | 判断影响面/用户受影响面以 tag 树、发行物内容、二进制、实测请求为准；CHANGELOG/清单与产物不符即 blocker；「未复现」如实标注 not run，不得写成通过。 |
| **V6 修 bug 必 grep 同型兄弟** | 修一处缺陷时 grep 同模式调用点/同形状守卫/同谓词分支，本次一并修或明确登记；机制替换要列全「同形态的平行实现」清单（见 LESSONS I21）。 |

## 提交与文档

| 规则 | 复核者看什么 |
|---|---|
| **C1 提交信息走 UTF-8 文件 `-F`，body 带验证记录** | 禁 `git commit -m` 内联（Git Bash 反引号陷阱——报错但提交仍成功、信息静默缺段）；授权提交的 body 写「跑了什么定向、读数多少」；编辑后回读校验关键内容在场。 |
| **C2 文档契约与代码同源** | 行为域文档（`docs/architecture.md`、`docs/security-model.md`、`docs/ui-conventions.md`）改契约须同批更新；security-model 不变量变更先走 PIP；链接指源文件与具名符号，不复制实现；一个事实只写一处、他处链接。 |
| **C3 本机工具红线** | Git Bash 传 `/X` 参数一律 `.ps1` 化；robocopy 0~7 均成功；跨调用写文件用编辑工具（Bash 内 python/heredoc 可能不落盘）；中文请求体写 UTF-8 文件再 curl；含中文的 `.ps1` 用 pwsh 7 或纯 ASCII。 |

## 机制导入

| 规则 | 复核者看什么 |
|---|---|
| **M1 协议/钩子的失败策略必须显式成契约**（来源：插件仓 M1，其机制取自 magpie） | 新增/评审扩展面（descriptor 协议、MCP 工具、事件回调、sidecar 接口）时：①接口文档显式声明 fail-open（钩子坏了不拦业务，只计数/限流日志）还是 fail-closed（钩子缺失/异常时拒绝服务——安全、凭据、脱敏类属此档）；②「每事件一次」与「每会话一次」生命周期的钩子分开，不混在一个接口里；③注册函数一律返回注销句柄 + 内部幂等删除，绝不暴露内部列表；④fail-closed 点位必须有按需刷新路径，不允许重启生效。 |
| **M2 注释里点名的守卫必须真的存在，且守卫自身有反向验证**（来源：插件仓 L16/L7 实战） | 注释断言「已由某某守卫保证」时 grep 确认守卫在场；守卫类测试入库时配「摘掉被守卫的规则必须变红」的自证；新增守卫/扫描测试文件要登记进守卫清单（若建立），漏登只在 CI 全量时红。 |
| **M3 记忆与文档三层分工**（来源：插件仓 docs 体系） | 仓库文档写现状（事实源唯一）；提案与计划进 `docs/pips/`；教训账本只收可执行规则、事件叙事进 `docs/经验总结/`。改代码前先读账本；收口后顺手补记（有新教训才记，没有不硬凑）。 |
