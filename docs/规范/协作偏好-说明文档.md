# 协作偏好（AI 代理工作口径）

> 用户在 mybatis-plus-sql-visualizer 项目多轮协作中确认的工作方式，建仓时沉淀为 7shell 的协作口径。与本仓 [`AGENTS.md`](https://github.com/SongRenShuo/7shell/blob/main/AGENTS.md)、[`开发流程-派活与验收清单.md`](../开发流程-派活与验收清单.md) 冲突时以更严格者为准；本文件写「用户怎么要求做事」，不重复流程细节。

## 立项与实施

- **先立项再开工**：动手前先写计划/提案文档；实施者先证伪计划里的「待验证前提」再落码。大变更走 PIP（见 [`pips/README.md`](../pips/README.md)），任务级实施立时间戳计划文档。
- **验收清单要能照抄**：每项给操作路径 + 预期值 + 失败时的日志锚点 + 回退开关；「环境受限未验证」如实标注，不冒充通过。
- **实施计划的所有内容都要做**：「实施计划所有内容」指全部条目，不得自行缩成高优项或只做文档登记。
- **派发前核实任务状态**：立项/实施前先全分支、全工作树排查这活是否已有人做过或在做，防重复实施；缺陷/任务编号取号前先 grep 查重。
- **主控的统计结论也要被证伪**：计数类结论（多少处、多少个、覆盖几条）入文档前必须附产生它的命令与口径。

## 验证分工

- **性能问题先非 GUI 自证**：先通过非 GUI 用例验证（注入缝放大「慢」→ 断言新路径不触发同步检索 + 耗时上限），验证没问题再交 GUI 验收。
- **最终 GUI 验收由用户做**：助手交付编号步骤 + 预期结果 + 失败时该看的日志行 + 判读口径，不代用户点 GUI；用户在用电脑时不占用桌面跑 GUI 自动化。
- **优化不得收窄兼容面**：收窄候选源/搜索范围类优化必须配「未命中回补链 + 跨形态用例」，不许为了提速把某个平台/协议/形态静默排除——漏掉的形态在测试夹具里往往看不见。

## 授权边界

- **文档、代码、合流、发行、推送是五个独立许可**：一次「允许」只覆盖它明说的那件事；「只更新 md，不用改代码」意味着先前的代码授权作废，新指令与在跑的写操作冲突时先回退再改文档。
- **清理类任务未授权不得删改任何文件**：分析阶段只读，先出风险分档表等逐组勾选；授权当次逐组有效，未勾的不许顺带清。
- **对外动作（push/tag/发行/外发内容）须用户明确授权**（AGENTS.md 第 7 条的重申）。
- **发行物/构建产物判「能不能发」看门禁读数与树的干净状态**，不看自述（LESSONS I35）。

## 文案与界面

- **面向用户的变更日志要简写**：一条一主题、每条短行（≤60~80 字），宁 8 条短不要 4 条长；只写用户可见结果，根因与读数留在内部记录。段序按 Added→Fixed→Changed。
- **界面文案要教会用户「怎么填」**：行标签显示内部编号时用户会怀疑东西坏了；标签取条件文本、输入区给常驻说明、置灰要说明原因与替代入口。
- **错误提示写界面真实存在的标签页名 + 当场可核对的一件事**（例：「设置 → 外观 → 字体，这个下拉里应有等宽字体」），不写抽象设置项名，不引导用户改无关文件。
- **新 UI 交互照抄仓内既有同类实现**：一致性优先于自创。
- **显示格式严格跟随设置**：空间不够应丢整块信息或截断，不是把字段缩写成另一种格式。
- **产品描述禁用能力清单替换口号**：摘要给钩子、清单是正文的活；「支持 N 种 X」这类罗列不做标题。

## 异步与并行

- **后台任务禁阻塞等待**：长命令 `run_in_background` 启动 → 主控继续做不依赖读数的事 → 只在完成通知后取数；禁 sleep 轮询、禁阻塞式等待输出（细则见派活清单）。
- **达标即提交**：给子代理派活写死「每完成一件可提交的就立即提交」；报告给按时间顺序的提交哈希清单。
- **并行紧张时转主控直接实施**：派活前探余量，子代理失败/被叫停后不原样重派，接手前先审计工作树有无半成品。
