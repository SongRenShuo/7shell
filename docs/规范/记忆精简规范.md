# 记忆精简规范

> 规范本地记忆文件（`~/.zcode/cli/memories/projects/<本项目>/memory/`）的管理，防止无限增长导致上下文膨胀。机制导入自 mybatis-plus-sql-visualizer 仓同名规范。
> **适用**：每次完成功能开发或修复后，主动判断记忆去向。

---

## 1. 三类记忆与去向

| 类型 | 特征 | 去向 |
|------|------|------|
| **核心知识** | 架构、模型、约定、活跃功能（未完成/待实施） | 保留在项目 memory |
| **已完成记录** | 已交付的功能、已修复的 bug、已解决的踩坑 | 移入 `docs/memory-archive/` |
| **通用经验** | 平台/框架陷阱、方法论、用户偏好（跨项目复用） | 移入 `~/.zcode/cli/memories/global/` |

### 保留标准（全部满足才保留）

- 下次开发**仍需参考**（如架构决策、协议映射）
- 处于**活跃状态**（功能待实施、问题未彻底解决）
- **仅本项目独有**（否则归 global）

### 归档标准（满足任一即归档）

- 功能已交付且发行
- Bug 已修复且测试全绿
- 踩坑已解决且不会以相同形态复现
- 开发计划执行完毕

### 全局标准（满足任一即归 global）

- Rust/Tauri/SSH 领域通用陷阱（非本项目特有）
- 多智能体协调方法论
- 用户偏好/环境配置

---

## 2. 归档目录结构

```
docs/memory-archive/
├── README.md          # 归档索引（导航清单）
├── bug-fixes/         # 已修复 bug / 已完成功能
├── pitfalls/          # 已解决踩坑
└── methodology/       # 智能体方法论（备用）
```

### 归档索引维护

每次归档新增文件后，同步更新 `README.md` 中对应分类表格：新增一行（文件名 + 一句话摘要）+ 更新底部统计。

---

## 3. 操作流程

### 归档操作（每次完成功能/修复后）

1. **判断**：按 §1 标准确定去向（保留 / 归档 / 全局）
2. **移动**：`mv` 文件到对应归档子目录
3. **更新归档索引**：`docs/memory-archive/README.md` 新增条目
4. **更新项目索引**：从项目 `MEMORY.md` 删除已移出条目
5. **提交**：`git add` 归档文件 + 索引，`git commit`

### 定期审视（每 2~4 周或记忆增长 20%+ 时）

1. 列出项目 memory 全部文件
2. 逐文件按 §1 标准重新分类
3. 批量移动 + 更新索引

---

## 4. 数量基线

| 位置 | 基线 | 预警线 |
|------|------|--------|
| 项目 memory（含 MEMORY.md） | ~15 | >25 |
| 归档 archive | 持续增长（历史记录） | — |
| 全局 global | ~40 | >60 |

超过预警线时触发定期审视。

---

> **原则**：记忆是开发过程的副产品，不是纪念品。已完成的记录就该归档，让活跃知识保持精简。
