# 开发流程：派活与验收清单

> 本文是 `AGENTS.md` 第 3 条指向的作业细则：主控怎么派活、子代理怎么交活、收口怎么验收。只写可执行动作，规则来自多轮并行开发的实际返工点（机制与模板导入自 mybatis-plus-sql-visualizer 仓并按本仓命令面适配）。

## 一、派活模板

每条派活必须写死以下六项，缺一项就会在现场临时猜：

1. **工作树与分支**：`git worktree add .worktrees/<名> -b <名> <基线>`；分支用扁平名，不用 `feature/` 前缀（第三方工具曾连坐删除 `feature/` 整目录）；本地独有分支尽快 push 留底。
2. **写集**：列出该车道会碰的文件/目录，并保证与其它车道互斥；`CHANGELOG`、共享文档这类多车道共写的文件提前说明冲突处理方式（禁用 stash 挪别家在途文档——见 LESSONS I23）。
3. **只跑定向**：Rust 用 `cargo test -p <crate> <测试名>`；前端用 `pnpm vitest run <文件>`；守卫用 `pnpm test:guards`。明令**不跑全量**（`pnpm check` / `cargo test --workspace`）、**不 `clean`**、不跑构建校验。全量门禁由收口阶段统一跑一次。
4. **并行登记**：跑长构建前 `python C:/Users/USER/.zcode/cli/parallel_tasks.py check`；有活跃任务先 `register --name <名> --sandbox <工作树绝对路径>`，跑完 `done --name <名>`（禁裸 `done`，它会注销全部活跃任务）。
5. **提交纪律**：每完成一件可提交的就立即提交（掉线时未提交的成果全丢）；`git add` 具体文件、禁 `-A`；消息写 UTF-8 文件后 `git commit -F`（消息里禁反引号；中文写文件传递，Bash 直传必乱码）。
6. **报告字段**：改动文件、提交哈希、定向读数（N/失败/错误/skip，逐例口径）、反向验证读数、未完成项与风险。没跑过的读数不许写「全绿」。

红线（每条派活都写）：不 push、不合流、不建 tag、不对外发内容；不碰别人的工作树；计划/文档回写只写自己工作树里的副本，主仓副本只读。

## 二、验收清单

1. **读数可复核**：读数要能对上测试输出或 CI 日志，不接受「全绿」两个字；腿绿先读逐例口径（见 LESSONS I4）。
2. **反向验证**：每条修复至少一条「摘掉必红」探针，贴摘除与还原两次读数；反向前先算清夹具沿途的闸门（LESSONS I7），摘除后 grep 自证生效（LESSONS I8）。守卫/扫描类改动还要证明探针有判别力——合成样本只能证明「规则看得见我造的形态」。
3. **not run 条款**：没跑的测试、门禁、真机逐项列「没跑 + 为什么」；环境受限只能写「环境受限未验证」，不得拿受限环境读数冒充验证通过。
4. **合并复核**：冲突按「保留双方」解；合并后在集成分支重跑定向——各支自报读数之和不是权威读数。收口回归**按 CI job 的步骤清单逐项跑**（Interface 是 `fmt:check` → `lint` → `typecheck` → `vitest` 四步合取），不是只跑 test——车道自报的关卡各是单项，凑不齐合取（LESSONS A5）。
5. **文档三件**：计划/PIP 状态回填、`CHANGELOG.md`（带提交哈希）、归属文档（`docs/architecture.md` / `security-model.md`）改契约同批更新。

## 三、测试三档分层

1. **定向**——每个实施子代理自己跑，随报告交出（见派活模板第 3 项）。
2. **统一全量门禁**——全部子代理完成后**单派一个只读收口代理**（或主控亲自）跑一次权威全量（`pnpm check` + `cargo test --workspace` + `cargo clippy`）；主控同时写文档收尾，并行不空等。收口代理只读；主控并行写文档期间不得碰 `src/`——一旦改了生产代码，那道绿立刻过期，必须复跑。
3. **构建校验**——`tauri build` / `pnpm app:e2e` 只在大改动或发版前跑（大改动判据：动依赖版本、动 crate 依赖方向、动 descriptors 协议、动 security-model 不变量、引入新平台接口）。

## 四、并行与资源

- 构建并发默认上限 2 路；瓶颈是**内存提交量不是 CPU**（Windows 上用内存 commit 读数判断，别看 CPU）；用户显式放开才可突破。
- 长命令一律后台启动，禁 sleep 轮询；输出全量落盘 + 回显真退出码（LESSONS I27）；子代理拿不到锁就记录证据交回主控复跑，不空等。
- 子代理并发默认 ≤3（账户限流）；派活前确认当前车道数；并行紧张时转主控直接实施。
- **多组并行部署/运维任务**：主控把「作业基准」写成共享文件（唯一事实源），凭据只放权限 600 的文件、基准里只写变量名；组间抢资源/孤儿进程由主控读证据后统一处置，不叫子代理自己 kill；判据落在磁盘字节与实连（LESSONS I25）。
- **会话粒度 token 治理**：省 token 的主杠杆是会话粒度不是提示词——上下文到 12~15 万就收口、写交接文档、开新会话；一个可提交单元一个会话；探索交给子代理、只回收结论。交接文档字段固定：分支与 tip / 已完成 / 未完成 / 证据读数 / 下一步 / 踩过的坑。方法论见 [`docs/经验总结/20261117-2200-并行开发与子代理协作方法论-经验总结.md`](经验总结/20261117-2200-并行开发与子代理协作方法论-经验总结.md)。

## 五、常见坑

- **工作树的 `.git` 是文件不是目录**：提交消息写临时文件（如 `/tmp/msg.txt`），不要写 `.git/COMMIT_MSG`。
- **Windows 长路径删不掉**：用 `\\?\` 前缀 + `rd /s /q`，写成 `.ps1` 执行（Git Bash 会把 `/X` 参数当路径转义）。
- **新增 i18n 键**要所有 locale 双份并过 `pnpm check:i18n`；只加英文不够。
- **改 descriptors 协议**先跑 `pnpm generate:descriptors` 再提交，`pnpm check:descriptors` 红就是忘了同步生成物。
- **新增守卫测试**要过架构守卫的登记面；注释里点名「已由某某守卫保证」前先 grep 确认守卫在场（LESSONS I3）。
- **Rust 依赖新库**走 CONTRIBUTING 的高门槛（cargo-deny 许可清单）；引入前先看标准库与既有 crate 能否覆盖。
