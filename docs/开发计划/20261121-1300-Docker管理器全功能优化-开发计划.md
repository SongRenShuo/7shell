## 一、现状事实（2026-11-21 核对）

**我们已有（desktop Docker 窗口 + 引擎适配层）：**

1. **信息架构**：桌面布局 220px 左导航五页签（概览/容器/镜像/网络/Compose）+ 计数徽标 + 能力位裁剪（`composeAvailable`/`networkAvailable` 探测，未连通只留概览）——`ContainerPane.vue:116-135`。应用 tab 另有 flat 紧凑布局同源。
2. **概览页**：三行可点击摘要（点击按状态/镜像跳列表）+ CPU/内存/网络三条迷你图（5s 采样、窗口非在前/文档不可见即停）+ 健康灯——`DockerOverview.vue`、`dockerMetrics.ts:93`（`engineHealthy` 只看 `dead`/`error` 两态）。
3. **容器列表**：300px 搜索、仅运行中默认开（`ContainerListView.vue:118`）、状态筛选、镜像/状态 chip、9 态浅底 WbTag（`containerStates.ts`）；行内写操作加载文案（starting/stopping/…）；删除确认带数据丢失后果 + `acknowledged` 旗标；行菜单：启停/重启/终端/日志/监控/文件/重命名/commit/clone/删除。表格自带 760px 最小宽、列表 scroller 内横滚（`ContainerListView.vue:608`；整列 850px 地板已在 `caa9f8e` 有意撤除）。
4. **详情/日志抽屉**：详情七段 + JSON + 复制；日志 tail 100/500/2000、时间戳、换行、**暂停不丢行**（backlog 回放）、有界缓冲 5000 行（`container.ts:56`）、重连按钮；「仅错误」是正则启发（`ContainerDetailDrawer.vue:70`），非真搜索。
5. **终端/文件**：exec 开 pty 进终端 tab（`store.exec`）；容器文件浏览经 `files.rs`（2690 行）进文件工作台。
6. **镜像页**：使用状态列（关联容器数）、pull 对话框（名称/tag 语法即时校验）、**检查更新**（`image_remote_digest`，能力位 `manifestInspectAvailable`，5 步确认弹窗 `ImageUpdateDialog.vue`，同镜像防重复）、任务面板（pull/push 分层进度解析、可停止、可展开日志）、registry 登录、load/save/tag/commit/prune；**加速源/代理是只读事实卡**（`RegistryCard.vue`——「写 daemon 配置是红线」，只提供复制 fragment）。
7. **网络页**：列表（驱动/子网/网关/IPRange/IPv6/关联容器数）、创建、删除护栏（in-use 由引擎报错，`manager.rs:480`）。
8. **Compose 页**：项目列表（状态/服务数/容器数）、up（detach/attach 流）/down/restart/logs（复用容器流通道）、writeYaml（名称语法 + 目录校验 + 缩进轻检查，`compose.ts`）；运行中只读提示。
9. **创建向导**：三步（基本/高级分区卡/确认信息）+ clone 预填（inspect → raw 解析 privileged/capabilities/labels/networks/limits，`ContainerPane.vue:224`）。
10. **引擎面**（`manager.rs`，CLI argv 适配 docker/podman/nerdctl/wslc，local+SSH 双 runner）：list/inspect/action/rename/create/stats/images/image_inspect/image_history/pull/push(流)/image_remove/image_prune/tag/load/commit/registry_login/namespaces/runtime_info/registry_settings(只读)/image_remote_digest/logs(流)/network_list/create/remove/compose_available/ls/ps/up/down/restart/logs/exec(pty)。`ps` 格式串无 `.Health` 列（`commands.rs:34`）。
11. **可靠性现状**：refresh 有 in-flight 去重（`container.ts:669`）+ 逐会话序列号防过期答案回写；流注册先于后端写入、路由按 streamId、晚到的行落空而非落到已关闭视图（`container.ts:519-548`）。**无事件流**——列表只在手动 refresh、action 后 refresh 时更新；流断线后只有人肉重连按钮。

## 二、最高技术决策（先读这里）

| # | 决策 | 内容 |
|---|---|---|
| **D1** | **批量 = FE 逐条编排 + 汇总，不加引擎批量命令** | 多选批量启停/删除走既有 `action` 逐条调用 + per-row 加载文案复用；失败汇总「共 N 项、前 10 条」复用 the reference 文案纪律。引擎不加 batch 语义：破坏性操作的 policy/acknowledged 闸门必须逐个过。 |
| **D2** | **升级/重建 = 「先拉新、后删旧」的 FE 事务** | 一键升级编排：inspect 抓原参数（复用 clonePrefillOf）→ pull 新镜像（任务面板）→ **pull 成功后**才 stop → rm → create（原参数+新镜像）→ start。任一步失败停在可重试处、绝不静默删容器；确认弹窗列明「命名卷保留 / 匿名卷丢失」后果。不新增引擎命令——CLI 本无 recreate-from-JSON，Portainer Rebuild 同为编排语义。 |
| **D3** | **事件流是新引擎命令，带重连与降级** | 新增只读 `container_events_start`（`docker events --format json`，能力位探测 `eventsAvailable`），走既有 stream 通道；FE 收到事件去抖 300ms 后定向 refresh（容器行级更新优先全量 refresh 兜底）；断线指数退避自动重连（1s/2s/4s/…上限 30s），重连成功即强制全量 refresh；能力位为 no 的引擎保持纯手动 refresh，不降级弹错。 |
| **D4** | **日志搜索在既有 buffer 上做，不加流** | 5000 行 buffer 已在内存：关键词/正则过滤 + 高亮 + 上/下跳转 + 命中计数在 FE 完成，不重发流、不动引擎。「多容器合并日志」= FE 多路流复用（每行加容器名前缀），流通道已有。 |
| **D5** | **清理中心 = 新只读命令先行 + 分级确认** | 新引擎命令：`system_df`（`docker system df`）、`container_prune`、`volume_list`/`volume_create`/`volume_remove`、`build_cache_prune`。全部带 acknowledged + 确认弹窗列明将回收的字节数（df 先查后删，先见数字再动手）。volumes 页先做只读列表 + 删除护栏（引用检查=引擎报错转义），创建缓行。 |
| **D6** | **注册表设置写入是 security-model 红线升级，先走 PIP** | 加速源列表（可排序）+ 代理表单的受控写入触及 daemon.json——按仓库规约动 security-model 不变量先走 [docs/pips](../../docs/pips/README.md)。PIP 未过不实施；PIP 通过前 RegistryCard 保持只读事实卡（其注释明言该红线）。 |
| **D7** | **healthcheck 进状态族，格式串加列** | `PS_FORMAT_DOCKER`（`commands.rs:34`）追加 `{{.Health}}`；`ContainerSummary` 增 `health?: string`；9 态表不动，health 作为容器行的独立徽标（starting/healthy/unhealthy），概览健康灯把 unhealthy 计入异常（`dockerMetrics.ts:93` 扩展）。wslc 等无此列的运行时返回空串即无徽标。 |
| **D8** | **列配置进 WebView localStorage（「两种状态两个家」纪律）** | 列可见性/顺序属 UI 偏好，无账号体系，进 localStorage；key 与既有桌面偏好同族命名。窄屏降级不做媒体查询魔法：<760px 维持表格横滚现状（地板语义已被 `caa9f8e` 裁定），只做列裁剪减少横滚需求。 |

## 六、边界与风险（明确不采纳与技术风险）

**明确不采纳（及理由）：**

1. **跨主机编排 / 多 agent**（Komodo、Dockge agent）：我们的多主机形态是多 SSH 连接，一 tab 一引擎；引入 agent 常驻是产品形态变更，非功能补齐。
2. **RBAC / 多用户 / 审计**（Portainer BE）：单用户桌面无服务端，权限模型无处安放。
3. **Webhook 自动重部署**（Portainer）：需要常驻 HTTP 端点接注册表回调；桌面应用不做常驻服务。其能力由批次三的「一键升级」手动化承接，后续若做计划任务档位再评估。
4. **SQL 查日志**（Dozzle）与**日志持久化/离线搜索**：与「不存储」纪律冲突，buffer 有界是特性不是缺陷。
5. **AI 助手/云 Offload**（Docker Desktop Gordon/Offload）、**K8s 转换**（Podman Desktop pod→K8s）：不同赛道；K8s 能力我们另有 k8s 面板。
6. **Fleet/GitOps 资源同步**（Rancher/Fleet、Komodo Resource Sync）：控制器与收敛循环错位于桌面形态。
7. **专门移动端**：无竞品先例，窄屏列裁剪已覆盖实际场景。
8. **无 shell 容器兜底终端**（Docker Debug）：需引擎注入工具箱，成本高收益低，先做失败提示。
9. **Shipwright**：不同类（K8s 镜像构建框架）；**Gui-for-docker**：不可查证。

**技术风险：**

- **D2 升级事务是编排不是原子操作**：rm 与 create 之间进程崩溃会留下「容器已删、新容器未建」状态——缓解：pull 成功才动手、create 失败时用同一 prefill 立即重试入口（失败横幅带「用原参数重建」按钮），并把「命名卷保留/匿名卷丢失」写进确认文案。重建后容器名冲突（旧容器删了但引擎延迟）按 the reference 错误码「容器名已存在」映射提示重试。
- **事件流在低配主机上的噪音**：`docker events` 全量开可能高频——实施时按类型过滤（container/image 两类）+ 去抖 + 「窗口非在前则只挂起不处理」（沿用可见性纪律）。
- **stats 列不做进批次二的原因**：列表内嵌采样与我们「没人看就不采样」纪律的边界含糊（列表可见≠用户在看指标），先不引入；ctop 式指标列留待后续单独裁定。
- **引擎命令扩面全部走 argv 适配**：wslc/nerdctl 对 df/volume/events 的支持不一致，每个新命令都要过 commands.rs 的运行时差异收口 + 能力位探测，不给不支持运行时画按钮（对齐「按钮不画则不失败」既有纪律）。
- **并行车道冲突**：`ContainerListView.vue` 当前有另一车道未提交改动（批量入口将落在同文件）——批次二开工前先取收口后 tip，逐 hunk 语义合并。
