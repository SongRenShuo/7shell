## 三、待验证前提

1. 车道 M 假设：把 rename/tag/create/restore 纳入 Caution 闸不会破坏现有 UI 流（这些动词的调用方当前不传 acknowledged）。实施者先证伪：检查全部调用方，决定「Caution 默认 allow + 记账」还是「要求确认」。**默认裁定：Caution（默认 allow）+ 记账一行**——与不变量 10 的范围一致（闸住 stop/remove/prune/delete/evict），非破坏动词只补审计可见性，不加交互。
2. 车道 N 假设：FileBrowser 当前渲染已窗口化（批次七裁定），目录内搜索（前端过滤）在 5000 条目下不破坏 perf 预算。实施者先跑 `FileBrowser.perf.spec.ts` 基线再加功能，搜索走**已加载列表的前端过滤**（不做远端 find——远端递归搜索是另一件事，不在本批）。
3. 两车道均不碰 `WorkbenchPane.vue`（P2-8 清理刚落，回归面已覆盖）。

## 四、车道契约

- **车道 M（Rust/policy）**：非破坏动词记账——container_rename/container_image_tag/container_create/trash_restore/move_to_trash 五动词经 `policy_decision` 记一行审计（subject 为路径/容器名），verdict Caution 默认 allow；补单测（每动词一行 journal）与既有行为回归。不碰前端。
- **车道 N（前端）**：FileBrowser 目录内搜索——工具条过滤输入 + 高亮/计数 + 空态句子，走前端过滤（预前提 2）；补 perf 对照读数。en/zh 同步。

纪律照旧：定向测试、可提交即提交（`git commit -F`）、长命令 run_in_background、计划文档主仓副本只读、并发 主控+2。
