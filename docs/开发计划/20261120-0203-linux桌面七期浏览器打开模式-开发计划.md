# Linux 桌面七期：浏览器打开模式（桌面托管给浏览器）— 开发计划（立项）

> 2026-11-20 立项，基线 `desktop-fnos-iteration`（tip `cd49349`，含五期批次一/二合并与车道 R 在途）。
> 目标用户口径：**「我希望这个 Linux 桌面可以直接在浏览器内打开（默认还是应用内），在这种模式下可以减少应用的内存占用」**。
> 与五期（Semi 视觉 + Docker 六页签）、六期（应用功能体验优化）**正交**：本计划不动 `ContainerPane`、不动应用级界面；触点是 `sevenshell-web`（拆 lib）、`src-tauri`（内嵌宿主模块）与桌面 tab 的 stub 形态。

## 一、最高技术决策：谁来托管浏览器会话（先读这里）

**仓库现状事实（2026-11-20 核查）**：

1. **浏览器宿主已存在雏形**：`crates/sevenshell-web`（bin 名 `sshell-web`）是「本地浏览器服务」——单个 axum Router（`main.rs:1773`）、只绑 `Ipv4Addr::LOCALHOST`（`main.rs:1789`）、每次启动随机 token（uuid v4，`main.rs:235`）、直接服务 `apps/desktop/dist` 的完整界面并应答全部后端契约（HTTP + WS）。头注自述「second host, not a second product：界面、核心、命令契约与桌面壳用的同一套」。真机验收（103.36.220.245 走查）就是用它 + 浏览器自动化跑的——**桌面工作台在浏览器里已经能跑**。
2. 但它是**独立第二产物**：自带独立 Vault、独立设置、独立会话列表（与应用内互不相通），没有从应用交接的入口——今天的用法是"另起一个进程、再配一遍连接"，不是"把当前桌面交给浏览器"。
3. **应用内已有 HTTP 服务器先例**：`src-tauri/src/mcp/server.rs`（MCP 端点）就在应用进程里跑 axum：loopback 绑定 + host_is_loopback 校验 + token 定长比较（timing-safe）+ 无 token 一律拒绝。axum 已在 `src-tauri/Cargo.toml:25`。
4. 前端已有宿主分支点：`apps/desktop/src/lib/runtime.ts` 的 `isDesktopRuntime()`（`__TAURI_INTERNALS__` 探测）；引擎命令「web/tauri 双宿主」是五期以来一直在执行的纪律。
5. 内存实测（四期验收，CDP 新进程法）：渲染器私有字节 home 42.3MB / 终端 84.8MB / **桌面 63.1MB / 桌面+终端窗 79.3MB**——桌面 tab 的 UI 成本几乎全在渲染器，SSH 核心在宿主进程，不随 UI 搬家。

| 路线 | 内容 | 判定 |
|---|---|---|
| **A：应用内嵌宿主（推荐）** | `sevenshell-web` 拆 **lib + bin**（Router/handlers 进 lib，bin 变薄壳）；`src-tauri` 内嵌同一 Router，**直接复用应用进程里现存的 Core 与 Vault**——「在浏览器中打开桌面」= 启动 listener → 拼 URL → 系统浏览器打开 → 应用内桌面 tab 收成轻量 stub | **采用** |
| B：sidecar `sshell-web` | 应用拉起独立 bin 交接。硬伤：bin 自带独立 Vault/设置，「这条连接」在另一个进程里要重建，交接变成"重新配置"；且多一个常驻进程与跨进程握手 | 否 |
| C：现 `sshell-web` 打磨就收 | 只优化独立形态。没有回答用户口径——"默认在应用内、想把当前桌面放进浏览器"这个动作不存在 | 否 |

**为什么 A 成立**：交接的对象是"这条连接"——Core 对象、Vault、设置、事件流全在应用进程里，内嵌宿主拿 `Arc` 就能直接复用，浏览器侧看到的就是应用内的同一份状态（同一会话列表、同一转发、同一桌面）；axum 在 src-tauri 已是依赖、MCP server 已有应用内 HTTP 安全先例，零新依赖类。bin 拆 lib 后 `sshell-web` 独立形态原样保留（无头部署路径不变）。

**决策点 D1（已按推荐裁定）**：采用路线 A。

## 二、内存账（诚实框架，不过度承诺）

- 应用内桌面 tab 的渲染器成本 ≈ **63MB（纯桌面）～79MB（桌面+终端窗）** 私有字节，挂在应用的 WebView2 进程树上。
- 浏览器模式 = **这部分预算搬家，不是消失**：应用进程树（用户口径里的"应用内存占用"）确实少一块；系统净额取决于浏览器是否已在运行——已运行则浏览器共享代码页/进程基础设施，净增约一个标签页，通常远小于一个独立 WebView2 渲染器；未运行则大致平移。
- WebView2 本身就是 Edge 内核——"换浏览器"不是换引擎，是换宿主进程。真正划算的场景：**低配机多连接长会话、把应用主窗最小化只在浏览器留桌面、一台机器多开桌面时**。
- 批次三用同一连接做双模式实测回填数字（应用树私有字节 in-app vs stub+浏览器，浏览器侧另列），不许只报"省了"。

## 三、需求拆解（用户口径 → 事实缺口 → 批次）

| # | 口径 | 事实缺口 | 批次 |
|---|---|---|---|
| N1 | 桌面可以直接在浏览器内打开 | 入口不存在：应用内没有任何"交接"动作；`sevenshell-web` 是 bin-only（无 lib），核心对象无法被应用复用 | 一 |
| N2 | 默认还是应用内 | 内嵌宿主必须**默认关闭、按需启动、随最后会话停止**——不点入口 = 行为与今天完全一致 | 一 |
| N3 | 减少应用的内存占用 | 交接后应用内桌面 tab 要收成**轻量 stub**（不再是 WorkbenchPane 渲染器预算），浏览器标签页承接完整桌面 | 二 |
| N4 | 交接后体验不打折 | parity 走查：快捷键（Meta 在浏览器被 OS 吃掉）、窗口几何/图标/壁纸记忆（**不同端口 = 不同 origin，localStorage 与应用内互不相通**）、拖拽上传、下载、剪贴板、亮暗、i18n、beforeunload 离开护栏（`dropUpload.leaveWarning` 已有文案，接线面核实） | 二/三 |
| N5 | 交接后应用还能"收回来" | stub 托管卡（打开/复制 URL、说明、「收回应用内」一键还原）；浏览器标签页关闭 = 只解除托管，**不断连接** | 二 |

## 四、决策点（已按推荐裁定）

| # | 决策 | 裁定 | 理由 |
|---|---|---|---|
| D1 | 托管者 | 应用内嵌（路线 A） | 同进程 Core/Vault 直接复用；sidecar 的独立 Vault 是体验硬伤 |
| D2 | 交接后应用内 tab 去留 | **stub 托管卡**，不关 tab | 连接的 UI 锚点要留在应用内：可复制 URL、可收回、红线语义有处安放 |
| D3 | 浏览器标签页关闭语义 | **只解除托管，不断连接** | 连接归 stub 管；「关窗即关连接」红线指应用内窗口，浏览器 tab 关闭 ≠ 关窗——architecture.md 桌面红线节随批次四补一句 |
| D4 | 内嵌服务器生命周期 | 按需启动；最后一个浏览器 WS 会话断开后自动停；应用退出即停 | 不点入口 = 零存在；不常驻不吃空闲内存 |
| D5 | 暴露面 | 127.0.0.1 only + 每应用运行期随机 token；复用 `sshell-web` 既有机制与 MCP server 的 loopback/timing-safe 纪律 | URL token 批次二改为 **fragment 传递**（前端读 `location.hash`，不进地址栏 query、不落 history）；调用走 header，WS 握手沿用既有 query 通道 |
| D6 | 安全评审 | **轻量 PIP**（批次一落码前） | 应用进程新增一个面向浏览器的 HTTP 面，按 AGENTS.md 纪律走 `docs/pips/`：威胁模型 = `sshell-web` 已评审模型 + 三条新增事实（默认关闭 / 按需启动 / 随最后会话停止） |
| D7 | 交接入口形态 | 桌面 tab 右键菜单动作 + WorkbenchPane 顶部 chrome 动作并排一项 | 两处同指一个命令，键盘/鼠标两条路 |
| D8 | 范围 | **桌面先行**：交接入口锚在桌面 tab | 内嵌服务提供完整界面（与 `sshell-web` 一致），浏览器里其余界面天然可达，但不为它们做独立交接入口（后续按需另议） |
| D9 | 打包态静态资源 | **dist 走 Tauri bundle.resources + `resource_dir()` 解析；开发态回退 `apps/desktop/dist`** | 发布包里 Tauri 自定义协议在 webview 外不可达，浏览器必须走真实 HTTP；零新依赖（tauri 原生资源机制），NSIS 收口步复核 release 解析 |

## 五、批次划分

### 批次一：sevenshell-web 拆 lib + 应用内嵌宿主（车道 BR-R，Rust/契约）

- **PIP 先行**（D6）：**已落档 `docs/pips/PIP-0001-browser-host-embedding.md`（Accepted）**——嵌入宿主威胁模型、不变量复用清单、三条新增事实、D9 资源决策；车道 BR-R 从它起步。
- `sevenshell-web` 拆 **lib + bin**：Router/handlers/静态服务进 lib（`serve(core, vault, static_dir, port, token)` 注入式 API），bin 保持 CLI 行为零变化；既有测试全绿是拆分门槛。
- `src-tauri` 新增内嵌宿主模块：按需启动/停止（D4）、随机端口、运行期随机 token、URL 组装（含 deep link 目标）；tower-http 进 src-tauri 依赖（workspace 已有同版本，非新增类）。
- 新 tauri command `desktop_browser_open(session_id)`：启动/复用宿主 → 返回 URL → 用系统默认浏览器打开（复用 services 应用「浏览器打开」的既有机制）。
- 验收：`sshell-web` bin 行为零变化（现有 fixture 回归）；内嵌宿主单测（oneshot 路由法，沿 MCP server 先例）；无 token 请求一律拒绝的反向验证。

### 批次二：stub 托管卡 + deep link + 离开护栏（车道 BR-S，前端）

- 桌面 tab 第三形态：**stub 托管卡**（连接仍活）——URL 打开/复制、托管说明文案、「收回应用内」一键还原；en+zh 双语、spec。
- deep link：浏览器 URL hash 带 open 目标（`#token=…&open=desktop:<id>`）→ 启动后直开该桌面。
- 事件 socket 断开感知 → stub 提示「浏览器侧已离开，可收回」。
- beforeunload 护栏：传输进行中确认离开（复用既有 leaveWarning 文案）；编辑器未保存联动钩子预留（六期批次三落地后自动生效）。
- 验收：stub 形态 spec；收回后 WorkbenchPane 完整还原（几何/图标/壁纸记忆不丢）；应用级界面零 diff 走查。

### 批次三：parity 走查 + 内存数字（走查/修复）

- 浏览器环境 parity 清单逐项：Meta 快捷键审计（浏览器里 Meta 被 OS 吃掉的键位改注册 Alt 备路）、窗口几何/图标/壁纸记忆 origin 独立性（**不做跨模式同步**，文档写明）、拖拽上传、下载、剪贴板、亮暗主题、i18n、批次七窄窗规则在浏览器的表现。
- 真机 103.36.220.245 双模式内存实测：同一连接，应用树私有字节 in-app vs stub+浏览器（CDP 方法论复用），浏览器标签页侧数字另列；截图存档 `assets/`。
- 验收：parity 逐项过或记缺陷修复；数字带命令与佐证回填本文件。

### 批次四：收口

- 门禁全绿（`pnpm check` 15 步 + cargo 全套 + deny）；NSIS 重建 + 哈希。
- `docs/architecture.md`：宿主表补内嵌宿主事实 + 桌面红线节补 D3 一句；`docs/security-model.md` 若触及不变量以 PIP 落档为准。

## 八、风险

1. **拆 lib 面大**（main.rs 1795 行 + mcp/ai/agent/sync/zmodem 子模块）——bin 行为零变化 + 既有测试全绿是硬门槛；拆分与内嵌分两个提交单元，回退点清晰。
2. **同 Core 双 UI 并发**（应用与浏览器同开）——契约层本就单 Core 多客户端（现有 web 宿主已这样跑），事件广播保两侧同步；验收加一条「两侧同开互不打架」走查。
3. **攻击面**——应用进程多了 HTTP 面：PIP + 默认关闭 + loopback-only + 按需启停兜底；LAN 监听不做。
4. **内存账如实**：迁移不是消失（§二框架），验收数字不许只报"省了"。
5. **origin 记忆分裂**：WebView2 与浏览器端口不同 = 不同 origin，记忆互不相通——文档写明，不做同步（§九）。
6. 与五期批次三/四/五/七（ContainerPane 域）无写集交叠，可并行；与六期批次一（WorkbenchPane 终端窗基建）同文件——六期未开排期前本计划批次二先行，若并行按独立工作树纪律。

## 九、不做（本期裁剪）

- LAN/局域网监听、远程设备访问（安全模型红线，loopback-only 不动）；跨模式记忆同步（应用内 ↔ 浏览器 localStorage 双写）；`sshell-web` 独立形态的产品化（保持现状）；移动端适配；应用整体默认改浏览器模式（默认仍应用内——用户口径原话）；桌面像素流/VNC 化（架构事实：桌面 = SSH 连接上的工作台，不是远程桌面流）。
