### C. 验证批次

1. `cargo check`（登记并行任务）→ 重建 `Cargo.lock`、暴露 Rust 接缝。
2. `cargo fmt --all --check` → `cargo clippy --workspace --all-targets -- -D warnings` → `cargo test --workspace`。
3. `pnpm typecheck` → `pnpm lint` → `pnpm test`（双方测试并集，失败即接缝）→ `pnpm build`。
4. 全绿后 `git commit`（merge commit，消息注明上游基线 `b236617`），push，dispatch CI 验证。

### D. 风险与回退

- **合并中途放弃**：`git merge --abort`，分支回到 `41b0440`，无损伤。
- **合并后门禁红**：允许在 merge commit 之上追加修复提交（保持 merge 本身诚实），或在 CI 红时以 `git revert -m 1` 回退整个合并。
- **`_vts` 时钟类 flake**：新引入的上游测试若在同毫秒 mount→dispatch，会复现同类问题；出现即按 `41b0440` 的模式修夹具。
- **上游 release 机制**：合并后 `release.yml`/`scripts/update-manifest.mjs` 为上游 0.5.x 版本，与版本号 G1 一致；我方分支不再单独发版则无影响。
