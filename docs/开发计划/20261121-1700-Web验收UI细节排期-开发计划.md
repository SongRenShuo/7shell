### 巡检补充观察（2026-11-21 批次三验收时）

- **CONTAINER-COMMAND-FAILED 已二次复现并完成第一层排查**（2026-11-21 批次四验收时）：Docker 窗每次打开均出现「容器运行时拒绝了 docker ps.」横幅，容器列表一次为空（刷新后数据到位）。已排除：MaxSessions 未满（`journalctl -u ssh -n 60 | grep 'no more sessions'` = 0，此前 13 条匹配为正常 session opened/closed）；服务器 docker 本身健康（终端直跑 `docker ps --format '{{json .}}'` EXIT=0，且 ps 带 `.HealthStatus` 字段）。结论：失败发生在**应用引擎层**（sevenshell-container runner 的 SSH exec 路径，remote.rs），非服务器拒绝。**P2 排查单**：读 remote::run 的非零退出/通道错误归一路径，拿到失败 detail；修成「引擎命令失败保留 detail 上横幅 + 自动重试一次」。

### 已立项增强（2026-11-21 用户批准）

- **多连接承载**（车道 N 之后的接续）：`MaxSessions` 是每条连接的限额——通道预算接近上限时自动开第二条 SSH 连接（同认证）并把新通道路由过去，名额即翻倍。前置：车道 N 的 HeldChannels 记账器先合（记账器在 carrier 层，池在其上建）。被否方案备查：常驻 shell 通道复用命令（自造文本协议，退出码/stderr/二进制全要转义解析，否决）。服务器侧即时缓解：用户可自行调大 sshd `MaxSessions`。
