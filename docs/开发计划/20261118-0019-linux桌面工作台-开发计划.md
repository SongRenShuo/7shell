# Linux 桌面工作台（linuxDesk）开发计划

- 日期：2026-11-18（基线：song 分支 f460da4）
- 状态：待实施。方向已由用户拍板（见[调研报告](../调研报告/20261118-0017-linux桌面连接-调研报告.md)第四节：只做 Web 桌面工作台，真实桌面画面不做）。
- 决策依据：[cooldesktop-调研报告](../调研报告/20261117-2356-cooldesktop-调研报告.md)、[gmssh-调研报告](../调研报告/20261118-0007-gmssh-调研报告.md)、仓内协议架构盘点。

## 一、目标与非目标

**MVP 交付（一期）**：新增连接类型「Linux 桌面」（协议 id `linuxDesk`）。它是一条普通 SSH 连接，但连接后的默认 tab 是工作台面板：

1. 系统卡：主机名、系统标志（复用 HostSystem 映射）、运行读数（CPU/内存/磁盘，复用 monitor 采样与速率换算）。
2. 文件快捷区：主目录等入口的图标区，点击打开本会话的文件浏览器 tab（SFTP，共用同一连接）；最近访问入口记在 WebView 本地存储（同 recent sessions 的用法记忆口径，不进设置文件）。
3. 会话卡：连接状态、已验证的主机密钥指纹、加密连接的既得事实展示。
4. 入口区：打开终端（同 handle 的终端 tab，懒挂载）、打开文件浏览器、打开监控页。

**非目标（写清楚，防止范围爬升）**：

- 真实桌面画面（VNC/RFB/像素流）——用户已拍板不做，将来另立提案（备选证据在调研报告第四节）。
- 远端任何落盘/部署：无 GA agent 式远端组件，无 sshd_config 改写（GMSSH 的两个反面教材）。
- 应用中心、回收站、磁盘管理、网络挂载、服务器对传、批量命令面板——backlog，见第六节。
- 新增 Tauri 命令、新增 crate、vault schema 升版——MVP 一概不需要（见待验证前提 5）。

## 三、待验证前提（实施者先证伪再动手）

1. **默认 tab 分叉点**：terminals.ts:822 的 open outcome 处理是否是唯一挂默认 tab 的位置（浏览器宿主 sevenshell-web 走同一前端代码，应同源；若有第二处挂签点会漏分叉）。验证法：grep `kind: "terminal"` 的构造点。
2. **编辑器零改动假设**：SessionDialog 对 linuxDesk 只需加 picker 分组，SSH 字段/认证方法渲染完全复用。验证法：加完描述符后真开一次编辑器。
3. **终端懒挂载兼容性**：terminals.ts 按 session.id 找终端 tab 的逻辑（:454 等）对「有 handle 但暂无终端 tab」的会话是否成立（文件浏览器「rides on a terminal's connection」的查找路径要能找到 handle 而不仅是 tab）。若不成立，最小修法是 linuxDesk 连接后仍挂一个隐藏的或直接挂载的终端 tab，由实测定。
4. **monitor_sample 与 session_system 对 linuxDesk 会话无协议门槛**：两处按 handle 取连接，不查协议（architecture.md 口径），预期成立，实测确认。
5. **vault 不升版**：Session 无新字段，LinuxDesk 会话随现有 schema 12 序列化无损。验证法：sevenshell-types/tests/wire.rs 加 LinuxDesk 会话夹具 + sevenshell-vault round-trip 测试（若有会话夹具文件）跑一遍。若 vault 的传输/备份测试按协议枚举遍历，会自动覆盖到。
6. **policy 分类器不按协议分派**：classification 按命令串，与协议无关（读 policy.rs 确认无 protocol 分支）。

## 五、派活与收口

- **车道划分**：P0 车道 A 先行落盘（生成物是车道 B 的依赖）；P1 车道 B 随后。两车道写集互斥。子代理并发 ≤3、构建并发 ≤2、跑长命令前 parallel_tasks.py check/register/done。
- **派活六项**（每条派活写死）：工作树 `git worktree add .worktrees/<名> -b <名> f460da4`（扁平分支名）；写集按上文任务条目；只跑定向（见各任务）；并行登记；提交纪律——每完成一件可提交的立即提交、git add 具体文件、消息写 UTF-8 文件 `git commit -F`、禁反引号、每笔提交过编译（`cargo check -p <crate>` / `pnpm typecheck`）；报告字段——改动文件、提交哈希、定向读数（逐例口径）、反向验证读数、未完成项与风险、跑门禁时树是否干净。
- **红线**：不 push、不合流、不建 tag；不碰别人工作树；CHANGELOG 与本计划文档由主控统一回填（车道不写）。
- **收口**：两车道完成后单派只读收口代理（独立沙盒、写集为空）跑一次权威全量 `pnpm check` + `cargo test --workspace` + `cargo clippy -- -D warnings`；主控并行写文档收尾，收口期间不碰 src/。构建校验（tauri build/app e2e）按「大改动」判据——本改动动 descriptors 协议，触发构建校验一档，发版前跑。
- **not run 条款**：真机联一台真实 Linux 主机（含无头服务器与带桌面环境各一）的手工验收项，单独列出「没跑 + 为什么」；环境受限的读数不得写成验证通过。

## 六、风险

1. **前端默认 tab 分叉遗漏第二挂签点**（待验证前提 1）——后患是浏览器宿主或重连路径挂错面板，表现为「连上直接进了终端」这类小偏差，收口时以真机点检兜底。
2. **术语与既有 RDP 文案混淆**：i18n 里 desktop 组现有文案面向 RDP 系统客户端；workbench 域的文案要避免「远程桌面」字样，统一叫「工作台」，防止用户把两者混为一谈。
3. **能力声明过宽**：linuxDesk 照抄 ssh 能力集的前提是这些能力在 UI 上全部对 linuxDesk 可用（协议能力同时驱动 policy 与将来的 agent 工具面）；若发现某能力对 linuxDesk 不该出现（如 recording），当次提交收紧声明，宁可窄不可宽。
