## 二、最高技术决策（先读这里）

| # | 决策 | 内容 |
|---|---|---|
| **D1** | **滚动条升级为全局默认，而不是逐个挂类** | `.scroll-thin` 的规则下沉到 `html, body, *` 层（`scrollbar-width: thin` + `scrollbar-color` 全局默认），WebKit 块同样全局化；`.scroll-thin` 保留为显式别名。内滚容器一律 `scrollbar-gutter: stable`，带圆角+边框的面板用 `overflow: hidden` 外壳包裹，滚动条永远落在边框之内。**验收即「应用里不再出现任何一根原生粗滚动条」** |
| **D2** | **选中态高亮永不压边框** | 列表/树行高亮一律「容器留 padding、行内缩 + 行自身圆角」（或 `box-shadow: inset` 方案），行背景与容器边框之间必须有边框宽度的间隙；横向全出血高亮视为违例。落成 `globals.css` 里一个可复用的行选中工具类，文件树/会话列表/设置列表统一换用 |
| **D3** | **浮层定位纪律** | 所有 popover/hover 卡：定位后按视口 clamp（左溢出翻转到右侧、上溢出下翻）；统一 popover z-index 梯度表。侧栏信息卡为第一个整改对象 |
| **D4** | **侧栏快捷行重构** | 「新建会话」按钮改为图标+文字自适应（或收成纯图标 + tooltip），图标群改溢出菜单；搜索行给最小可用宽度。**文字截断在本面板视为违例** |
| **D5** | **令牌单一来源 + 截图回归闭环** | 全部新规则只写进 `globals.css` 的令牌/工具类层，组件只消费；每批次用 browser-use 对同角度截图前后对比留档（`docs/开发计划/assets/`），vitest/typecheck/build/CI 照常把关 |

## 五、风险与边界

- 全局滚动条改动触及每个滚动面，风险集中在「样式全局化后个别自定义滚动条（如 ColorPicker、ColumnResizeHandle）双重定义」——实施时以 `git grep scrollbar` 全量盘点后统一收敛到一处。
- Web（浏览器）与桌面 WebView2 的滚动条表现不同源：以 Web 实测为准，桌面端抽样核对。
- 本计划只覆盖视觉/交互细节，不动功能逻辑；纯 CSS/模板改动，测试面以现有快照为主。
