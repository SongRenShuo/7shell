# Linux 桌面工作台二期：桌面化增强开发计划

- 日期：2026-11-18（基线：song 分支 cf03ae6；一期见 [20261118-0019-linux桌面工作台-开发计划.md](20261118-0019-linux桌面工作台-开发计划.md)，已实施）
- 状态：待评审启动。用户反馈：一期的工作台「缺失太多基础功能，甚至连桌面首页都没有」——期望是**真正的桌面隐喻**，不是一张卡片页。
- 需求来源：[the reference product 调研报告](../调研报告/20261118-0007-product-research.md) 第四节的桌面功能全集 + cooldesktop 调研报告的交互范式 + 一期真机使用反馈。

## 一、需求分析：对标与裁定

the reference product「桌面」的功能全集（其实证 API 面）：桌面图标与位置、壁纸、回收站、快捷方式、应用中心、任务管理器、文件管理器、磁盘管理、网络挂载、系统设置、AI 助手。逐项对照 7shell 的三条约束（零远端 footprint / 无命令不上机 / destructive 走 policy 矩阵）裁定：

| the reference product 功能 | 裁定 | 理由与 7shell 形态 |
|---|---|---|
| 桌面首页（壁纸 + 图标 + 双击） | **采纳，一期缺口** | 一期是卡片信息页，不是桌面。二期 P0：壁纸满铺整个 tab + 桌面图标网格 + 双击打开 + 右键菜单 |
| 桌面快捷方式 | **采纳** | 图标 = 系统入口（文件/终端/监控/回收站）+ 用户添加的目录/路径快捷方式 |
| 回收站 | **采纳，改造** | freedesktop Trash 规范（`~/.local/share/Trash/files+info`），全程 SFTP 操作、零 footprint；the reference product 是 agent 侧 `.Recycle_bin`，不学 |
| 任务管理器 | **采纳，增强** | 监控进程页已有只读列表；补「结束进程」（policy: destructive + 确认 + 审计，命令常量 `kill <pid>`） |
| 文件管理器 | 已有 | 一期已打通（SFTP 浏览器骑工作台连接），P0 接进桌面图标 |
| 系统设置 | **部分采纳** | 只读系统信息聚合（OS/内核/时区/主机名/运行时长）+ 电源（已有）；改主机名/时区类写操作留 backlog |
| 壁纸 | 已有，增强 | 一期是会话字段四选一；二期桌面满铺渲染 + 桌面设置项（图标布局） |
| 磁盘管理（分区/格式化） | **backlog** | 高危写操作，危害等级 catastrophic 级，须单独立项走 security-model 论证 |
| 网络挂载（NFS/SMB） | **backlog** | the reference product 在远端装客户端实现（有 footprint），与零 footprint 约束冲突，需要时单独立项 |
| 应用中心 | **裁掉** | 7shell 无应用生态；桌面图标即入口 |
| 服务器对传 | **backlog** | 差异化功能，与本目标（桌面化）正交 |
| AI 助手入桌面 | **backlog** | 助手面板已存在，桌面入口图标可选加 |

## 二、一期现状与差距

一期工作台 = `WorkbenchPane.vue`（463 行）：系统卡 + 文件快捷区（主目录 + 最近访问）+ 会话卡/入口 + 电源。数据全部骑工作台 SSH 连接（session_system / monitor_sample / SFTP），零远端部署。缺的正是「桌面感」：壁纸没有满铺、没有图标、没有双击/右键交互、没有回收站、没有任务栏。

## 三、分期与任务

### P0 桌面首页（核心交付，2~4 天）

把工作台 tab 从「卡片页」重构为「桌面」：

1. **壁纸满铺**：`WorkbenchSettings.wallpaper` 的背景铺满整个 tab（现只铺卡片底层），文字/图标浮于其上；无壁纸时用 elevation 表面色。
2. **桌面图标网格**：左上起网格排列——系统图标固定区（主目录、文件管理器、终端、监控、回收站[占位至 P2]、电源）+ 用户快捷方式区；图标 = 图形 + 名称，单击选中、**双击打开**（桌面惯例），也支持回车打开。
3. **右键菜单**：桌面空白处（刷新、新建快捷方式[占位 P1]、桌面设置）；图标上（打开、从桌面移除、属性[占位 P1]）——复用既有 useContextMenu。
4. **底部薄任务栏**：显示本会话已打开的 tab（终端/文件/监控）一键切换——跨 tab 的桌面内导航，替代一期「入口卡按钮」。
5. 原系统卡内容收进「系统信息」图标入口（弹层或 inspect 页复用，推荐后者——监控页已是该数据的放大版，桌面图标直达 inspect）。
6. i18n en + zh-CN 双份（workbench 域）；WorkbenchPane.spec 重写为桌面版用例；弹窗/菜单触点按[弹窗克制红线](../规范/设计规范-弹窗克制红线.md)登记。

写集：`components/workspace/WorkbenchPane.vue`（重构）、新增 `lib/workbench/desktopIcons.ts`、`WorkspaceTabs.vue`（如需）、stores/terminals.ts（任务栏联动，若有）、i18n workbench.json ×2、对应 spec。

### P1 快捷方式与图标管理（1~2 天）

1. 用户添加快捷方式：选远端目录（复用文件浏览器导航或路径输入）→ 生成图标；删除快捷方式。
2. 位置记忆：图标顺序/位置记 WebView 存储，按 session id（沿用 `lib/workbench/recentPaths.ts` 的用法记忆口径，不进 settings/vault——桌面布局是设备偏好不是会话数据）。
3. 定向：desktopIcons spec + WorkbenchPane spec 快捷方式用例。

### P2 回收站（2~3 天，触及文件删除语义）

1. 后端：SFTP 实现回收站语义——删除 = 移入 `~/.local/share/Trash/files/` + 写 `info/*.trashinfo`（原路径+删除时间）；还原 = 移回；清空 = 删 Trash 下内容。全部是固定模式 + 用户路径经既有 SFTP 通道，无新命令、无新 footprint。
2. **语义切换**：文件浏览器与桌面删除默认「进回收站」，设置可切回「直接删除」（显式选择，默认更安全）。
3. 回收站图标入口 → 回收站浏览器（列出 files/、支持还原/单删/清空）；清空走 policy（destructive，确认对话 + 审计）。
4. wire 类型：回收站条目/操作结果进 sevenshell-types（camelCase 守卫覆盖）；错误码按需新增（SFTP 通道复用，预计复用既有码 + 一两个新构造器）。
5. 定向：types wire 测试 + core 回收站操作单测（含 trashinfo 解析/还原路径校验——路径是敌意输入，按 container files 的 quoting/tar-slip 同级标准防越界）+ 前端 spec。

### P3 任务管理器增强（1 天）

1. 进程页（inspect）加「结束进程」行操作：确认对话 + policy（destructive）+ 审计；命令常量 `kill <pid>`（pid 数字格式化注入，沿 monitor 的 pid 规则）。
2. 定向：policy 矩阵用例 + core 用例（deny 先于连接查找）+ 前端确认流 spec。

### P4 桌面设置（1 天）

壁纸四选一已有；补桌面项：图标大小档、任务栏开关。进 WorkbenchSettings（若加字段→vault schema 14 迁移链，按流程走）或 WebView 偏好（推荐后者：布局类偏好不进 vault）。

### Backlog（记录不排期）

磁盘管理、网络挂载、应用中心、服务器对传、AI 入口、写类系统设置（主机名/时区）。

## 四、待验证前提（实施者先证伪）

1. **freedesktop Trash 兼容性**：目标机器（Ubuntu 22.04 实测通过）`~/.local/share/Trash` 是否被 gio/文件管理器共用；trashinfo 格式字段（Path 需 URL 编码）以 gio 规范为准，先在真机手工验证一轮再写实现。
2. **跨文件系统移动语义**：SFTP 无 rename 跨设备保证——同分区 rename 原子、跨分区需 copy+delete；删除大文件进回收站的耗时与进度表现要在真机量过再定交互（量大时禁用进回收站或提示）。
3. **任务栏与 WorkspaceTabs 的联动深度**：薄任务栏是「tab 条的镜像」还是「桌面内独立状态」——若纯镜像则零后端改动；若要在桌面内关闭 tab，需要 terminals store 的既有 closeTab 直连（预计成立）。
4. **双击与单击选中在 Web/WebView 的触控表现**：双击延迟与选中态在两宿主一致。
5. **回收站入口的图标语义**：回收站「空/非空」状态需要一次 SFTP 探测——探测频率钉在「打开桌面时一次」，不做常驻轮询（监控面板的采样纪律）。

## 六、风险

1. **删除语义变更**是本期最大的行为变更：默认进回收站会改变文件浏览器既有交互（传输面板/失败重试的语义连带）——P2 先做灰度开关再默认切换，switch 前真机验证三条删除路径（列表删除/多选删除/拖拽外的全部入口）。
2. **桌面隐喻的度**：图标网格 + 任务栏做薄，防止滑向「在 SSH 客户端里仿操作系统」的过度工程——the reference product 的桌面是它的产品核心，7shell 的桌面是 SSH 会话的前页，深浅以一期调研结论（工作台=会话 front page）为界。
3. **trashinfo 防越界**：还原路径来自 trashinfo 文件（远端内容=敌意输入），必须按 container files 同级标准校验（拒 `..`/绝对路径逃逸/控制字符）。
4. **vault schema 触发**：P4 若选择把桌面项放进会话字段会触发 schema 14——推荐 WebView 偏好路线避开迁移。

## 八、第三批（2026-11-18 同日）：系统面板与桌面可读性

用户反馈两条：**图标压在壁纸上看不清**、**功能还是太少**。本批针对这两条落地。

### 8.1 对比度（先修，用户可见）

根因不是配色而是**语义**：图标与文字用的是 `text-foreground`，浅色主题下是近黑色，压在深色壁纸（四款壁纸全是暗色渐变）上不可读。修法是「壁纸上的 chrome 不再跟随主题」——壁纸是张图，其上的图标/文字固定为白色 + 投影（`drop-shadow` / `text-shadow`），选中态用 `bg-white/15`；无壁纸时仍走主题前景色，原路径不变。`onPicture` 一个计算属性决定这一分支。

### 8.2 系统面板（吸收 the reference product 的功能全集里可安全吸收的部分）

the reference product 桌面功能对照（继续遵守三条约束：零远端足迹 / 无命令不上机 / destructive 走 policy）：

| the reference product 功能 | 本批裁定 |
|---|---|
| 服务/进程管理 | **采纳**：服务列表（systemd 状态四列）+ 启动/重启/停止（stop 为 destructive，确认对话 + 审计） |
| 磁盘管理 | **采纳只读**：块设备树（含分区、文件系统、挂载点、型号） |
| 用户管理 | **采纳只读**：可登录账户（UID/GID/主目录/Shell/是否在线/root 标注） |
| 网络设置 | **采纳只读**：网卡（双栈地址 + 收发字节）、路由、DNS 解析器 |
| 日志查看 | **采纳**：journal 尾部 200→500 行，逐次加量 |
| 系统信息 | **采纳**：发行版/内核/运行时长/时区，面板页首常驻 |
| 应用中心 / 网络挂载 / 磁盘格式化 | 仍不做（无应用生态 / 需远端装客户端 / catastrophic 级需单独立项） |

### 8.3 实现落点

- 契约：`crates/sevenshell-types/src/sysinfo.rs`（9 个类型，camelCase，Option 省略）+ 前端 `types/sysinfo.ts` 镜像。
- 核心：`crates/sevenshell-core/src/sysinfo.rs`——11 条固定命令常量、纯解析函数、`system_overview` / `journal_tail` / `service_action`；unit 名走白名单（字母数字与 `@ . : _ -`），非法名在命令拼装前拒绝。
- policy：`service_action`（start/enable/disable/reload/restart = Caution，stop = Destructive，未知 = Catastrophic）。
- 错误：`SERVICE-ACTION-FAILED`（具体服务端回话进 detail）。
- 双宿主：`system_overview` / `system_journal` / `system_service_action` 三命令同时注册。
- 界面：`components/workspace/SystemPanel.vue`（五分区 + 常驻事实行 + 服务行操作 + 停止确认），桌面新增「系统面板」门，与回收站互斥（一次只站一个面板）。

### 8.4 读数

- `cargo test -p sevenshell-core --lib sysinfo`：**19/19**（16 解析夹具 + 3 条 unit 名白名单／注入拒绝）。
- `cargo test -p sevenshell-policy service`：**4/4**。
- `cargo check --workspace --all-targets`：绿。
- 前端：`WorkbenchPane.spec` **20/20**（含「开一个面板会关掉另一个」「切分区面板不塌」「叶子磁盘带不出 children 键」），`vue-tsc` 零错。

### 8.5 真机验收（103.36.220.245，浏览器宿主 + 真实界面）

五个分区全部读到真实数据：服务 147 条（含 `fwupd-refresh.service loaded failed failed`）、磁盘（`loop0 61.9M loop squashfs /snap/core20/1434`）、可登录账户 31 条、网卡 17 条（`eth0 UP 103.36.220.245/24`）、路由 4 条、journal 200 行真实的 sshd 认证失败。壁纸上的图标已是白色 + 投影。

验收抓出一枚只在真机出现的契约 bug：点开「磁盘」分区面板整块消失，控制台是 `e is not iterable`。根因是 Rust 侧 `children` 为空时 `skip_serializing_if` 不上线，TS 镜像却把它写成必填，`for…of undefined` 抛出后 Vue 把子树卸了、界面上什么都看不到。修法三件套：镜像改成可选并写明原因、flatten 接受 `undefined`、用例用**壳层真实会发的形状**（叶子不带键、父盘带分区）钉住。这条记入 `docs/LESSONS.md`：**空集合省略是线格式的常态，镜像必须按「可能不在」写**。

## 九、第四批：把只读纵深做满（the reference product 继续吸收）

用户第三次提「功能还是太少」。对照 the reference product 的 833 键语言文件逐个过了一遍，结论先说：**它有几样能力本仓已经有了**——端口转发（`ssh.yaml` 的 forwarding / dynamicForwarding / agentForwarding）、批量执行、终端多标签与重连、文件管理与传输、任务管理器、AI 助手；**有几样是明确不做的**——应用中心（要远端装客户端）、磁盘格式化与网络挂载（catastrophic 级，需单独立项）、自动改写远端 sshd_config 打通转发（对目标主机有侵入性，反面教材）。

### 9.1 后端：四条新的固定读

沿用既有纪律：固定命令常量、无任何人输入的值拼进命令、一次 `SystemOverview` 全带回、某条命令宿主不答就留空而不是整体失败。

| 读 | 固定命令 | 落点 |
|---|---|---|
| 服务开机自启 | `systemctl list-unit-files --type=service --no-pager --no-legend --plain` | 与 `list-units` 按 unit 名合并，`ServiceEntry.enabled`（enabled / disabled / static / masked / indirect / disabled-runtime） |
| 定时任务 | `crontab -l` | `SystemOverview.crontab`：逐行（去注释、去空行） |
| 登录记录 | `last -n 20 -w` | `SystemOverview.logins`：用户 / 终端 / 来源 / 起止 / 时长，`still logged in` 单列 |
| 防火墙 | `ufw status`、`firewall-cmd --state` | `SystemOverview.firewall`：任一回话即用；两条都答「command not found」时为「未安装」，不是错误 |

服务开关（enable/disable）的 policy 与后端命令**已经存在**（`service_risk.rs`、`systemctl enable|disable`），本批只补界面。

### 9.2 界面

- 服务分区：每行多一个「开机自启」开关（enable / disable，Caution，失败回滚并提示）；`static` / `masked` 一类不可切换的状态，开关置灰并说明原因。
- 新分区「定时任务」：`crontab -l` 的原始行，等宽字体，空时写明「该用户没有定时任务」。
- 新分区「登录记录」：最后 20 次登录，在线的一行标出。
- 网络分区尾部一行防火墙状态（ufw active / firewalld running / not installed）。
- 磁盘分区：每个挂载点一条用量环（数据来自监控样本已有的 `df -kP`，**不新增命令**），用量按已用/总量取整，超过 90% 标红。
