# Linux 桌面连接：两项目调研综述与方向决策

> 日期：2026-11-18。输入材料：[20261117-2356-cooldesktop-调研报告.md](20261117-2356-cooldesktop-调研报告.md)、对标 SSH 桌面产品的形态调研（由子代理独立完成，主控抽查复核过承重结论）、7shell 仓内架构盘点（行号见第四节）。
> 决策记录：2026-11-18 用户拍板——主线只做 Web 桌面工作台，真实桌面画面（像素流）不做，留待将来另立提案。

## 一、最重要的一致发现

两个参考产品的「Linux 桌面」都不是远程桌面的像素流，这是本次调研最有价值的结论，直接决定了技术路线：

- **对标 SSH 桌面产品**：桌面是本地服务托管的 Web 单页应用，客户端以 webview 内嵌本地页面；壁纸、图标、回收站、应用中心、任务管理器全部是前端画的桌面隐喻，数据经 SSH 到远端的 agent 取回。其全部前端产物中 VNC/noVNC/X11 抓屏/H264/WebRTC 指纹计数为 0。
- **cooldesktop**：连远端 agent 都没有——「桌面」就是浏览器里 Vue 自绘的窗口管理器壳（DOM 拖拽窗口 + iframe 内嵌 Web 应用 + xterm.js 终端），与远程主机的真实画面完全无关；全仓 grep 不到任何 X11/Xvfb/Wayland/VNC/截屏/Robot 痕迹（已做对照查询证伪搜索接口失效的可能）。

这背后有一个产品现实：SSH 客户端的连接对象绝大多数是无头服务器，上面根本没有可渲染的桌面。「Linux 桌面」在这类产品里的真实含义是**一台主机的可视化管理工作台**，借用操作系统的隐喻组织文件、监控、终端和应用入口。

## 二、两项目精华与反面教材

按「正面学什么、反面避什么」浓缩（细节与行号证据见两份报告）：

| 来源 | 精华（可平移） | 反面教材（要避开） |
|---|---|---|
| 对标 SSH 桌面产品 | 桌面隐喻的文件/系统面板是「Linux 桌面」需求的低成本解法，比像素流便宜一个数量级，且对无头服务器同样可用；隧道四类型配「场景示例」的解释式 UX（本地 Navicat 连 3306 实际访问服务器 MySQL 这类文案）；创建前端口占用预检；连接表单/分组树/跳板链/代理的字段模型；零知识云同步（本地加密后上传）；凭据 AES 加密落盘分层 | 远端自动部署常驻 agent（root 权限、远端落盘）；未开 AllowTcpForwarding 时自动备份并改写远端 sshd_config（即便带回滚也越权）；主窗口 nodeIntegration: true；登录通道内嵌可提取的共享 RSA 私钥 |
| cooldesktop | STOMP 主题分层 + JSON 三元组消息体 + 单一推送收敛点 + 离线缓冲 + 末位断开清理；「提交任务即返回 taskId + 完成后推送结果」的异步 UX；分片上传的完整性校验与合并锁；敏感配置双向过滤（不返回也不允许写） | 认证押在闭源魔改 Tomcat 上（构建不可复现）；WS 层零鉴权 + allowedOrigins("*")；密码明文落盘且重置强制大写；SQL 字符串拼接；终端 resize 用定长 4 位数字段按下标切割的脆弱协议 |

与 7shell「Linux 桌面」画面采集直接相关的技术（X11 抓屏、帧编码、视频流），两个项目都没有——真实桌面画面若将来要做，参考对象应是 noVNC、xrdp、RustDesk 一类项目，这一点两份报告都已写明。

## 三、与 7shell 架构的匹配分析

7shell 的安全模型明确拒绝对标产品式的远端 footprint：不在用户主机上自动部署常驻 agent、不擅自改远端配置、无命令不上机（「commands nobody typed are a constant」）。好消息是，Web 桌面工作台恰好**不需要任何远端部署**：工作台要的每一类数据，7shell 现有面上全都有了，全部 rides 在用户已经打开的那条 SSH 连接上。

现有资产盘点（行号为 2026-11-18 基线 f460da4 实测）：

| 工作台需要 | 现有资产 | 出处 |
|---|---|---|
| 操作系统标志与身份 | `session_system` 固定只读命令（uname/os-release）+ 前端图标映射 | docs/architecture.md「The system mark beside a session」；`lib/system/icons.ts` |
| CPU/内存/网络/磁盘读数 | `monitor_sample` 单条固定命令采样 + 前端速率换算 | `crates/sevenshell-core/src/monitor.rs`；`lib/monitor/rates.ts` |
| 文件浏览/传输 | SFTP 文件工作台 + 传输面板 | `sevenshell-sftp`；`components/files/` |
| 终端入口 | 同一连接上的终端 tab | `stores/terminals.ts:822`（open outcome 挂终端 tab） |
| 跳板/端口转发 | 路由逐跳验证 + forwards 随会话拉起 | docs/architecture.md「Routes and forwards」 |
| 主机密钥信任流 | 探测 → 决策 → 重验，与普通 SSH 完全一致 | docs/security-model.md 不变量 2/3 |

后端足迹因此极小：新增一个协议身份 + 前端一个工作台面板，核心复用。协议匹配点全仓清点过——Rust 侧按协议分派的位置只有 `crates/sevenshell-core/src/sessions.rs:211`（终端开启分派）与 `:395`（流式终端守卫）两处需要接新变体，其余对协议的比较（`files.rs:353/356` 的 WebDAV/FTP 特判、`sevenshell-api` 的 container 特判等）不命中新协议即自动落到 SSH 路径，正是想要的行为。编译器会兜住一切非通配 match；通配 match 与 `==` 比较的扫查已列入开发计划第一项任务。

前端落点同样收敛：`WorkspaceTab` 联合类型在 `stores/terminals.ts:251`，连接后的默认开签在 `:822-828`，协议选择器分组在 `components/sessions/SessionDialog.vue:94-99`（desktop 分组现只有 rdp）。归档提交 c981da4 曾建过嵌入式 RDP 引擎的 `desktop` tab 形态（tab kind + 面板组件 + i18n 域 + Tauri 裸字节帧通道），其骨架结构可作为接线参考——但工作台不画像素，帧通道那套不需要恢复。

## 四、方向决策记录

2026-11-18 用户在三个选项中拍板：**只做 Web 桌面工作台**（与两个参考项目对齐，范围最紧、风险最小），真实桌面画面留待将来另立提案。被放弃的两条路线的证据保留如下，避免将来重复调研：

- **真实桌面画面（VNC/RFB over SSH + canvas 渲染）**：技术上可行——7shell 已有 SSH 通道承载任意 TCP 服务的能力（k8s CONNECT 桥、端口转发），归档引擎 c981da4 证明过进程内 canvas + 批量脏矩形 + 输入回传的完整形态；但仅对装了桌面环境的主机有意义（x11vnc 等），且 RFB 客户端或远端抓屏 helper 都是不小的实现量。将来若立项，从 noVNC/xrdp/RustDesk 与归档引擎两头取材。
- **混合先行（工作台 + 真桌面分期）**：即「两期都做」，用户未选；如方向变化按本节证据重启即可。

## 五、命名与形态定案

- 协议 id：`linuxDesk`；Rust 变体 `LinuxDesk`；标签 `protocol.linuxDesk.label`＝「Linux 桌面」（英文 "Linux desktop"）。
- defaultPort 22（底层就是 SSH 连接）、runtime `native`、transport `tcp`、supportLevel `connect`；能力面先照抄 ssh.yaml 中它真正兑现的子集（shell/exec/resize/keepalive/hostMetrics/sftp/scp/jumpHost/forwarding/dynamicForwarding/recording），另加一个新能力 `workbench`（desktop 组）标记「该协议开工作台面板」，供前端定默认 tab 与将来的 agent 工具面使用。agentForwarding 不声明——工作台用不到，不 honest 的能力不写。
- 前端：新 tab kind `workbench`，面板组件 `WorkbenchPane.vue`，i18n 域 `workbench.json`（en + zh-CN 双份，`pnpm check:i18n` 把关）；linuxDesk 会话连接后默认挂工作台 tab，终端/文件/监控页仍可从工作台进入，共用同一条连接。
- 会话模型不加新字段：linuxDesk 复用 Session 的 host/port/user/auth/jump/forwards，不需要 vault schema 升版（wire 测试补 LinuxDesk 夹具验证序列化即可）。
