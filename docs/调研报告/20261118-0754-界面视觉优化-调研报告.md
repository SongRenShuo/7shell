# 界面视觉优化：可行方案调研与推荐

> 日期：2026-11-18。输入材料：[界面视觉现状盘点-调研报告](20261118-0300-界面视觉现状盘点-调研报告.md)（子代理实测盘点，全部数字带 文件:行号 出处）、外部设计趋势调研（参照产品与暗色主题体系，出处见文末）、主控真机截图四张（工作区/文件/工作台/终端，2026-11-18 真机测试留档）。
> 用户判断：目前 UI 太丑，需要全部优化。本报告回答「丑在哪、有什么可行路线、推荐哪条」。

## 结论速览

1. 「丑」的根源不在设计体系，在体系的**应用层**：token 层（989 行 globals.css，全 oklch，12+1 套配色 × 2 主题）是教科书级的，缺的是把它变好看的最后四块——真实字体、字号锚点、Button 抽象、动效。
2. 四块硬证据：字体栈首位的 Inter/JetBrains Mono **从未被加载**（全仓无字体文件，实际渲染是系统默认字）；`text-base` 全仓 **0 次**、`text-xs` 585 次（小字海洋，无层级锚点）；431 个裸 `<button>` 零共享抽象（cva 声明了却 0 处使用）；443 次 transition 里 426 次是 transition-colors，对话框/toast/下拉全部硬切无进出场。
3. 暗色主题是「单层平面灰」：缺 elevation 阶梯（暗色的层级靠表面逐层提亮 + 低透明度描边，不靠阴影——这是现代暗色界面的第一定律），整窗一个灰度，观感即「工具灰」。
4. 可行路线三条：**方案 A** 现有 token 体系上补齐四块 + elevation（零新依赖，推荐）；**方案 B** 引入 shadcn-vue/reka-ui 头无组件库替换自研基础件（可访问性白拿，但与仓的约定宪法/守卫测试冲突面大，只宜局部按需）；**方案 C** 整库换 Arco/Naive（GMSSH 路线，最快但与 Tailwind 体系、13 套调色板、最小依赖哲学全冲突，不推荐）。
5. 推荐 **A + 个性化深化捆绑**：字体自托管 → Button/输入基础件（cva）→ 动效 token 与进出场 → elevation 表面阶梯 → 全业务域跟随。全程不动 token 架构、不推倒 13 套调色板、不加组件库依赖。
6. 改 UI 前必须先过的门：**形态预览评审先行**（LESSONS I26：争议方案先给用户看形态，用户点头才落码）；新的字号层级要先修订 ui-conventions.md 与 typography 守卫（现在守卫钉的是「四字号、不过 medium」的旧宪法）。
7. 高风险耦合已定位：17 个守卫测试直接断言源码文本（tables/typography/selection/windowCsp）；CSP `style-src 'unsafe-inline'` 是 xterm 生命线不可动；xterm 不吃 oklch，「CSS 变量→JS 读取→xterm theme」链路必须保住；spec 对类名耦合很小（3 文件 11 处），e2e 主要耦合文案。

## 一、「丑」的根因（证据先行）

盘点报告的实测数字指向四个「缺」和一个「平」：

| 短板 | 证据 | 用户观感的对应 |
|---|---|---|
| 字体是假的 | 字体栈声明 Inter/JetBrains Mono 但全仓无字体文件、无 @font-face | 每个字都是系统默认字形，谈不上气质 |
| 没有字号锚点 | text-base 0 次；text-xs 585 + text-[11px] 540 + text-[10px] 179 次 | 满屏小灰字，没有「这是标题、这是重点」的节奏 |
| 组件无抽象 | 431 个裸 button 零共享；同一按钮配方字符串重复十余种变体 | 按钮手感不一致，圆角/内距/焦点态各自为政 |
| 动效缺位 | animate-in/out 0 次；对话框/toast/下拉硬切 | 界面「死板」，交互没有回应感 |
| 暗色单层平面 | 无 elevation 阶梯，整窗同一表面灰度 | 「工具灰」，无纵深无质感 |

值得强调：这些是**体系的欠账**而不是体系的错误——token 架构、选区宪法、表格系统、类型守卫都是高质量的地基。所以全部优化的正确姿势是「在地基上盖楼」，不是「换地基」。

## 二、外部参照与设计趋势

- **同类产品**：Termius（公认最精致的 SSH GUI：暗色为主、侧栏主机管理、清晰的品牌色点缀）；Warp（块状输出、命令面板、强动效）；Wave（工作区集成、现代 Web 栈）。共同点：暗色默认、面板圆角化、侧栏即产品门面、品牌强调色克制使用、交互动效无处不在。
- **暗色 elevation 定律**（Atlassian/Material/社区共识）：暗色模式里阴影几乎不可见，层级靠**表面色逐层提亮**（surface-1 → surface-2 → …）+ **低透明白描边**（如 white/8%）表达；「上层表面比下层亮」是可读性的前提。
- **Tailwind v4 / shadcn 生态**：token 即杠杆（--background/--card/--border 语义层就是 elevation/质感旋钮）；半透明描边 + subtle shadow + 统一 radius 是「polished」配方的三件套；tweakcn 一类可视化 token 编辑器让主题迭代提速。
- 对 7shell 的直接含义：它的语义 token 名字（--card/--muted/--border…）已经就位，缺的是给这些 token 一套「有层次的取值」。

## 三、可行方案对比

| | 方案 A：现有体系补四块（推荐） | 方案 B：引入 shadcn-vue/reka-ui | 方案 C：整库换 Arco/Naive |
|---|---|---|---|
| 思路 | 字体自托管 + Button/输入基础件（cva）+ 动效 token + elevation 阶梯，逐域跟随 | 用头无组件库替换自研基础件，外观模板 shadcn 默认 | 换成熟组件库（GMSSH 同款路线） |
| 新依赖 | 0（字体文件属资产非依赖） | reka-ui（1 个，中量） | 重量级组件库 + 样式体系并存冲突 |
| 与仓「宪法」的相容 | 高：选区规则/表格系统/类型规则原样保留，只修订字号层级一节 | 冲突面大：自研件的守卫测试、选区约定、ui-conventions 全要重谈 | 全冲突：Tailwind 原子类体系被架空 |
| 13 套调色板 | 全部自动受益（token 取值升级） | 需逐个适配 | 全废 |
| 双宿主一致性 | 天然一致 | 需自验 | 需自验 |
| 视觉上限 | 高（参照 Termius 级可达成） | 中高（默认味重，需深度定制才不「一眼 shadcn」） | 中（库味重） |
| 工作量 | 大但可分期（基础件是杠杆点） | 中 | 小（但返工代价最大） |
| 判定 | **推荐** | 不全量替换；仅在键盘导航复杂件（如命令面板）按需引单件 | 否 |

## 四、推荐路线（A + 个性化深化捆绑）

按依赖顺序五步，每步独立可验收：

1. **字体真实化**：自托管 Inter（variable woff2，OFL 许可）+ JetBrains Mono，字体栈补 CJK 回退声明（中文界面走系统微软雅黑/苹方，避免打包中文字体的体积代价）。一步到位改变「每个字的气质」。
2. **基础件收编**：新建 Button 组件（cva 变体：primary/secondary/ghost/destructive × sm/md），输入/对话框/下拉/tab 跟进；431 个裸按钮按「先高频 20 处、后全量」渐进替换。
3. **动效体系**：duration/easing token（统一三档时长 + 两条缓动曲线，遵循 prefers-reduced-motion），对话框/toast/下拉进出场，tab 与列表 hover 微交互。
4. **elevation 阶梯**：暗色表面逐层提亮 + 低透明描边进 token（--surface-1/2/3 或等价语义），侧栏/主区/面板/浮层四级纵深；亮色主题对应加 subtle shadow。
5. **字号锚点回归**：页面标题/区块标题层级（text-base/lg）落位——**此前必须先修订 ui-conventions.md 类型节并同步 typography 守卫**（旧宪法钉死「四字号、不过 medium」，新的层级是宪法修订不是违反）。

个性化深化与 A 捆绑：palette 选择预览卡片化、强调色/密度/圆角档进外观设置域——13 套调色板 × 新 elevation 矩阵自动成立，是这套体系对方案 B/C 的压倒性优势。
