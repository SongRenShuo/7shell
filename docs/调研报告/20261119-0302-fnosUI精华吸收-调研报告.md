# fnOS UI 精华吸收：可行路线调研与推荐

> 日期：2026-11-19。输入材料：[fnOS UI 精华拆解-调研报告](20261119-0302-fnosUI精华拆解-调研报告.md)（子代理实证，ISO 解包 + 603 个原始源码文件 + 40 条点子清单）、[Linux 桌面功能盘点-调研报告](20261119-0302-linux桌面功能盘点-调研报告.md)（子代理实证，全部数字带 file:line）、三期计划批次五实施记录与批次六车道契约（`1f904dc`/`6314d38`）。
> 用户判断：「吸取 fnOS 的所有精华为我们所用，特别是 UI 交互和样式」「重点调研 Docker 管理器」「持续迭代直到生产级可用」。本报告回答「fnOS 好在哪、我们差在哪、抄什么怎么抄」。

## 结论速览

1. **fnOS 的精华不是某个组件，而是一整套「桌面即产品」的完成度**：设计 token 有明确档位（色三态浅底/时长三档/阴影三档语义），桌面壳有完整全局层（竖 dock 四段结构 + 搜索式 Launchpad + 可点击小部件 + 三类壁纸 + 通知/任务中心），所有写操作有 loading 态文案 + 错误码全量映射人话 + 破坏性操作分级确认。7shell 骨架已齐（三期半迭代、约 190 用例），缺的正是这三层「完成度皮肤」。
2. **最值得抄的十件事**（按杠杆排序）：① 桌面 chrome token 化（把 20+ 处内联 hex 换成 `--workbench-*` 变量族，fnOS 用 `theme-mode` 属性翻转全局变量的手法直接平移）；② 搜索式 Launchpad（380px 搜索 + 300ms 防抖 + auto-fill 网格 + 0.1s scale 进场）；③ dock 分段结构（桌面/全部应用/窗口列表/系统区 + 3px 激活左条替代运行圆点 + 「桌面」=全部最小化 toggle）；④ 窗口几何按用户持久化（fnOS 防抖 100ms 记 localStorage，7shell 三期遗留项正好补上）；⑤ 桌面小部件（系统/网络/磁盘/存储，每个可点开对应监控窗口——「小部件即入口」）；⑥ Docker 左导航六页签 + 容器 9 态浅底 tag + 概览页三行摘要 + 迷你实时图；⑦ 错误码→中文文案全量映射，绝不裸透传；⑧ 进度条 90/95% 阈值变色；⑨ 4px 细滚动条；⑩ Empty 插画 5 场景明暗双版。
3. **Docker 管理器是本次的对标重心**（用户点名）：fnOS 的 Docker 子应用=「概览/容器/Compose/镜像(计数徽标)/仓库/网络」左导航 + 创建容器两步向导（分区卡：端口/存储/环境变量/网络/capabilities/资源限制）+ 更新镜像 5 步确认清单 + 网络删除护栏。7shell 引擎已有 24 条容器命令（含创建/pull/stats/exec/日志流），UI 层按 fnOS 的信息架构重排即可立竿见影；Compose/网络管理需引擎扩展，列为可选批。
4. **吸收方式是「平移结构、不换血统」**：7shell 保留 Vue3+Tailwind+oklch token 体系与 teal 品牌色，吸收 fnOS 的变量命名法/档位思维/交互结构/文案纪律；不引 Semi、不做双设计系统、不换品牌蓝。
5. **两条既有结论被 fnOS 实证强化**：a)「视觉优化报告」的暗色 elevation 定律——fnOS 三档阴影各配 1px 低透明描边，正是同一配方；b)「没人看就不采样」纪律——fnOS 小部件 `visibilitychange` 才轮询，同一条纪律的两个独立发明。
6. **明确不抄**：Semi 全量引入、双设计系统并存、40px 超圆弹窗（工具语境 ≤16px）、全局禁用右键（7shell 文件管理需要完整右键菜单）、PingFang 优先字体栈、Montserrat 式「自托管却不用」的字体浪费。
7. 推荐路线：四期六批次——**批次一视觉地基（token 化+语言移植）→ 批次二 Docker 管理器 fnOS 化（重点）→ 批次三桌面形态升级（dock/Launchpad/小部件/壁纸/几何持久化）→ 批次四功能窗口（承接三期批次六车道契约）→ 批次五全局层（拖放上传/通知中心/空态/设置项）→ 批次六窗口深化与打磨收口**。每批独立可验收，详见[开发计划](../开发计划/20261119-0302-linux桌面四期fnOS体验对标-开发计划.md)。

## 一、fnOS 好在哪（对照 7shell 差在哪）

| 维度 | fnOS 做法（证据见拆解报告） | 7shell 现状（证据见盘点报告） | 差距定性 |
|---|---|---|---|

| 桌面形态 | 66px 竖 dock 四段+3px 激活条；Launchpad=搜索式全屏层；图标格 130×124+文字双阴影；小部件五件套可点击 | 悬浮任务栏每窗一格+运行圆点；启动器无搜索；图标 85px 格白字+阴影；无小部件 | **形态可平移** |
| 窗口模型 | 1100×640 默认、44px 标题栏、16/12 双圆角、几何按用户持久化（防抖 100ms）、关闭钮 hover 红 | 666×422、8px 圆角、几何不记忆（三期遗留）、关闭钮已 hover 红 | **补持久化+圆角档** |

## 二、吸收裁定

**直接吸收（结构与参数照搬）**：搜索式 Launchpad 尺寸/防抖/动效参数；dock 分段与激活左条语义；窗口几何持久化机制（key 设计按 kind+sessionId，防抖 100ms）；图标文字双阴影；进度阈值 90/95；4px 滚动条；表格列间分隔线+斑马纹变量；错误码映射表机制；确认弹窗后果式文案；loading 态文案枚举；`visibilitychange` 才轮询。

**改造吸收（换了实现载体）**：
- 桌面 chrome token 化——fnOS 用 `theme-mode` 属性 + `--semi-*` 变量；7shell 用 `[data-palette]`/`.dark` + 新增 `--workbench-*` 变量族（glass 面/描边/文字/激活色），桌面组件内联 hex 全量替换。亮色桌面从此可能。
- 小部件——fnOS 存服务端 `browser.desktopWidget`；7shell 无账号体系，进 WebView localStorage（遵循「两种状态两个家」既有纪律）。
- Empty 插画——fnOS 是设计资产 SVG；7shell 自绘 5 场景 × 明暗双版（NoData/LoadFailed/NoFile/NoHardDisk/NoSearchResult 同构）。
- Docker 概览迷你图——fnOS 用 recharts；7shell 自绘轻量 SVG 折线（禁动画纪律一致，不引库）。
- Compose/网络页——fnOS 全量；7shell 引擎无 compose/network 命令，UI 先按「概览/容器/镜像」三页签落地，Compose/网络作为引擎扩展可选批（需新增只读 `network list` 等命令再立项）。

**明确不抄**：Semi 全量引入（1MB JS+642KB CSS，与 Vue/Tailwind 体系冲突）；双设计系统并存（fnOS 自己的债，别学）；40px 超圆弹窗与 32px 登录卡（工具语境 ≤16px；登录卡若做限 16px）；全局禁用原生右键（7shell 文件管理右键是能力）；品牌蓝 #0066FF（保留 teal 血统，激活条/焦点环等「语义位」用既有 teal token）；PingFang 优先字体栈（Windows/Linux 走系统 UI 字体）。
