> 一句话总评：**这是一个已经跑完三期半迭代的「SSH 会话前页式桌面外壳」**——窗口系统、任务栏、启动器、图标管理、回收站、系统面板、Docker 管理器等骨架全部真实可用且测试扎实；但它仍是「单会话的单层桌面」：无多工作区/多壁纸生态、无桌面级全局能力（搜索/通知/快捷键/拖放）、视觉上桌面 chrome 与应用主题两套皮并行、个性化深度（壁纸仅 4 款纯 CSS 渐变）远不及成熟 NAS 桌面。

## 1. 组件盘点（apps/desktop/src/components/workspace/）

### 1.1 WorkbenchPane.vue（1567 行，桌面总装）

职责：Linux 桌面会话（协议 `linuxDesk`）的 front page，把「状态栏 + 桌面（图标网格/窗口层/启动器）+ 任务栏 + 对话框」组装成一个 tab（`WorkbenchPane.vue:1110-1565`）。

- **壁纸**：4 款 id（aurora/dawn/forest/plain，`WorkbenchPane.vue:7`），渐变写死在 `WALLPAPER_BACKDROPS`（`:150-155`）；会话字段 `session.workbench.wallpaper`（vault schema 13）+ 本窗口即时选择 `chosenWallpaper`，保存走 `backend.sessions.save`，失败回滚（`:997-1012`）。**无自定义图片壁纸**（应用壳层另有一套 Wallpaper/背景图，与工作台不通用）。
- **桌面图标**：8 个系统门（home/terminal/docker/monitor/systemInfo/system/transfers/trash，`:214-223`，monitor 与 systemInfo 双门同目的地）+ 用户快捷方式（localStorage 按 session id，上限 24，`desktopIcons.ts:22`）。图标=彩色底片+白色 lucide 线条（`toneOf`，`:535-557`）；壁纸上的 chrome 固定白字+阴影不随主题（`onPicture`，`:175`）。
- **交互**：单击选中、双击/回车打开（`:1168-1170`）、HTML5 drag 换位（`beginDrag/dropIcon`，`:274-314`，存储的是 id 序非坐标，`iconOrder.ts`）、图标右键菜单（打开/移除[仅快捷方式]/属性，`:853-886`）、桌面右键菜单（刷新/新建快捷方式/重置布局/桌面设置，`:807-845`，teal 皮 `tone:"desktop"`）。
- **窗口管理**：`windows` ref + 纯函数库（见 §2）；打开（`openRecord`，单例 id 或随机 id）、聚焦/最小化/最大化/还原/移动/缩放全部转发；关闭走 220ms 折叠动画后才删记录并关底层 tab/文件句柄（`close`，`:430-450`）。
- **窗口内容分派**：terminal→TerminalPane（含 ended+重连态 `:1236-1246`）、files→FileBrowser（独立 `files.open` 句柄）、monitor→HostPage+SystemReport、docker→WorkbenchDockerWindow（windowed container tab）、transfers→TransferPanel、system/trash→嵌入面板（`:1227-1298`）。
- **启动器**：8 瓦片（7 门+settings），`launch()` 开对应窗口或打开桌面设置（`:675-714`）。
- **任务栏数据**：每窗一格（含活动圆点状态），时钟每分钟走一次（`:761-792`），电源按钮合成右下角坐标打开电源菜单（重启/关机，走 policy 确认 `workbench_power`，`:1016-1098`）。
- **桌面设置对话框**：壁纸四选一（写回会话）+ 图标密度两档（localStorage `sevenshell-workbench-density`，`:969-1012, :1482-1554`）。
- **属性对话框**：图标名称/类型/打开内容，快捷方式另有路径/打开目录/复制路径/移除（`:943-967, :1397-1476`）。
- **i18n**：全部经 `vue-i18n`（`workbench.json` en/zh-CN 各 235 行），无硬编码文案。
- **样式手段**：Tailwind 工具类为主 + 少量内联 style（壁纸渐变、z-index）；对话框用 reka-ui DialogRoot 裸配 Tailwind（无 ui/ 基础件）。

### 1.2 WorkbenchWindow.vue（365 行，窗口铬）

- 纯展示+手势，无状态（props 进 emits 出，`WorkbenchWindow.vue:38-70`）。
- 视觉：`bg-[#000000c4]` + `backdrop-blur-[15px]`、圆角 8、阴影 `2px_6px_10px_2px_#00000091`、标题栏 ≥45px/17px 白字/ hairline `#ffffff12`、三圆钮（关闭 hover 变红 `#c50f1f`）（`:96-104, :230-277`）——CoolDesktop 参考度量。
- 手势：标题栏 pointer capture 拖动（从起始几何发绝对坐标，防夹取漂移 `:109-163`）；拖到 top≤0 自动最大化并结束拖动（`:153-157`）；双击标题栏最大化/还原（`:135-141`）；右下角 12×12 握把缩放，MIN 200×200（`:177-211`）。
- 动效：transform 过渡 200ms（max 300ms）、入场 `workbench-window-in` 0.16s、min=`scale(0)`、closing=`scaleY(0)`；`prefers-reduced-motion` 全关（`:311-348`，globals.css `:991-1003` 再兜一层）。**最小化不卸载内容**（transform 而非 v-if，保终端 scrollback，`:281-287`）。

### 1.3 WorkbenchStarter.vue（221 行，全屏启动器）

- 纯展示：`v-show`+`Transition` 0.4s 淡入出、关闭时 `inert`（`WorkbenchStarter.vue:68-78`）；Esc 关闭（window 级监听，`:57-64`）；点空白关闭；单击瓦片即启动（桌面图标才是双击，`:90-105`）。
- 度量：`#000000b8` 蒙层、140px 列/100px 瓦片/58px 底片、hover `#ffffff2e`+blur(15px)（`:116-219`）。z 层 20（任务栏 30、启动器宿主层 40，见 WorkbenchPane `:1316`）。

### 1.4 WorkbenchTaskbar.vue（252 行，悬浮任务栏）

- 57px 胶囊、左右 `clamp(0.5rem,6vw,73px)`、底边距 15px、圆角 12、`#00000082`+blur(5px) 双层（mask 层避免糊文字）（`:126-147`）。
- 格子 49×49：启动器格 + 每窗一格（32px 底片 + 5px 红色运行圆点 scale 0→1）+ 时钟 + 电源（`:160-250`）。无窗口预览、无右键菜单、无分组的合并同类。

### 1.5 WorkbenchStatusBar.vue（65 行，顶部状态栏）

- 23px 高、`#00000082`、13px 白字：左主机名（mono）、右用户/时钟/断开钮（`:37-63`）。断开=关闭 workbench tab（真关连接）。

### 1.6 WorkbenchDockerWindow.vue（85 行，Docker 窗口体）

- 承载既有 `ContainerPane`（不重写工作区）；mount 时 `containers.connect(tab)`（linuxDesk 走 `desktop_engine_open`，`container.ts:603`），unmount `forget`（`WorkbenchDockerWindow.vue:44-53`）；三态：连接中/失败（含错误码+重试）/工作区（`:56-84`）。

### 1.7 WorkbenchTransfersWindow.vue（19 行）

- 只是把应用级 `TransferPanel` 装进窗口（`WorkbenchTransfersWindow.vue:14-19`），无 tab 无连接，展示全会话传输。

### 1.8 TrashWindow.vue（251 行，回收站）

- freedesktop Trash（`~/.local/share/Trash/files+info`）面板：列表（名称/原路径/大小）、还原（无 sidecar 的条目禁还原）、永久删除、清空（ConfirmDialog+policy acknowledged=true）（`TrashWindow.vue:91-126`）；打开与每次变更后重读，无轮询（`:128-134`）；嵌入模式不画自己的标题栏。样式用 `lib/table.ts` TABLE 契约 + Tailwind，随应用主题（窗口内）。

### 1.9 SystemPanel.vue（约 800 行，系统面板）

- 7 分区（`SystemPanel.vue:88-96`）：Services（systemd 列表+start/restart/stop+boot 开关 enable/disable，stop 单独确认 `:198-228`）、Disks（块设备树 flatten `:124-134` + 真设备/根挂载用量环 `:177-195`，>90% 红线在模板）、Accounts、Network（网卡/路由/DNS/防火墙状态）、Crontab、Logins（last -n 20）、Journal（200→500 行逐次加量 `:263-266`）。
- 数据纪律：一次 `system_overview` 全带回+手动刷新，active 才读，无时钟采样（`:230-274`）；旧宿主缺字段显示空态句子不清零。
- 页首常驻事实行（发行版/内核/uptime/时区，`:101-112`）。

### 1.10 WorkspaceTabs.vue（约 950 行，顶部标签条）

- 应用级 tab 条；workbench tab 分支渲染 `WorkbenchPane`（`:885-915`）；`windowed` 的 terminal/container tab 不进标签条（谓词 `terminals.ts:326-331`），关闭窗口即关 tab；workbench 图标/关闭文案/ended 态处理（`:296-313, :630`）。
- 计划中的 `TabBody.vue` 抽取**未落地**（find 无此文件）——窗口复用内容改用「windowed 标记 + WorkbenchPane 内联分派」实现，行为等价但 WorkspaceTabs 仍保有各 tab 内容分支。

- `SplitDivider.vue`（面板分割条，非桌面专属）、`TerminalSchemeMenu.vue`（终端配色菜单，非桌面）。

## 4. 状态管理与数据流

- **terminals.ts**（`stores/terminals.ts`，~2100 行）：tab 总仓。`WorkbenchTab`（kind "workbench"，持 session+handle，`:218`）；协议支持 workbench 能力即默认挂 workbench tab（`:522`）；`openTerminalTab/openContainerTab` 接受 `windowed`（`:559, :286-291`），windowed tab 不进标签条、关窗即 `closeTab`（关连接/引擎）；连接断开时同步把 workbench.handle 置 null（`:454-462`）；重连=重开 workbench（`:1812`）。**桌面拖放文件不落地**：`browserHandleOf` 对 workbench 返回 null（`:1644-1654`）。
- **files.ts**：文件浏览器句柄仓；`files.open(sessionId)` 为文件窗口开独立 SFTP 浏览器，关窗即 `files.close(handle)`（WorkbenchPane `:446-448`）。删除默认进回收站：`preferences.ts:206 filesDeleteMode: "trash"`。
- **container.ts**：容器引擎仓；`connect()` 按 `tab.session.protocol === "linuxDesk"` 分叉到 `backend.containers.connectDesktop`（`:598-617`），其余容器命令原样复用。
- **sessionEditor.ts**：会话编辑器「工作台壁纸」节（`:493-496, :603`），vault schema 13。
- **composables**：`useContextMenu`（单例菜单 + `tone: "desktop"` teal 皮，`useContextMenu.ts:32-38`；ContextMenu.vue `:56-69` 渲染 `#17b38e` 白行）；`useWindowControls`（应用自身窗口控制，与桌面窗口无关）；`useToast`/`useTransferNotices`（回执）。
- 桌面 UI 状态（图标顺序/快捷方式/密度）全在 WebView localStorage，「两种状态两个家」：会话事实进 vault，设备偏好进 storage（`desktopIcons.ts:1-16`）。

## 5. 视觉现状

### 5.1 globals.css 与主题体系

- 设计 token 单一事实源：`:root` oklch 语义色 + `.dark` + 12 套 `[data-palette]`（`globals.css:16-166, :193-671`）；圆角由单一 `--radius`（0.625rem）+ 三档 `[data-corner-style]` 派生（`:81-102`）；布局 classic/separated 两套（`:104-135`）；终端色独立 `--terminal-*`（`:70-77`）。CSP `style-src 'self' 'unsafe-inline'` 硬约束（xterm inline style）。
- **桌面的特殊地位**：桌面 chrome（状态栏/图标/任务栏/启动器/窗口）完全不走这套 token——颜色全部内联在组件里（`#000000c4`/`#00000082`/`#17b38e`/`#d11010f5` 等），固定白字，故意不随亮暗主题（WorkbenchWindow 头注 `:1-30`；WorkbenchPane `onPicture` `:165-175`）；只有窗口**内部**的应用内容走主题。globals.css 里桌面相关仅一块 reduced-motion 降级（`:991-1003`）。
- 桌面自身度量全部来自 CoolDesktop 参考逐项实测（状态栏 23px、图标格 85px/40px 图、任务栏 57px/73px 边距/12px 圆角、窗口 666×422/8px 圆角/blur15、启动器 140px 列、菜单 teal `#17b38e`），见三期计划 §2.1 的度量表与代码落点。

### 5.2 调研报告既有结论摘引（docs/调研报告/20261118-0300）

- token 层全仓最规范，「丑」在应用层；字号失衡（text-xs 585 / 11px 540 / 10px 179 / text-sm 160 / text-base 0），层级靠灰度不靠字号。
- 431 个裸 `<button>`/91 文件无 Button 组件，cva 依赖闲置；动效词汇 96% 是 transition-colors，无进出场 token（工作台窗口/启动器是少数有真动效的地方）；focus-visible 仅 7/91 文件；无骨架屏；阴影无 elevation 体系；目标字体 Inter/JetBrains Mono 从未打包上屏；中文栈未定义。
- 硬编码 hex 全仓仅 14 处（其中 8 处就是 WorkbenchPane 壁纸渐变）；桌面 chrome 的内联深色系是第三处集中地（报告口径以 .vue hex 统计为主，桌面组件大量 `#xxxxxxx` 半透明字面量在其统计之外——盘点时实测 WorkbenchWindow/Taskbar/Starter/StatusBar/ContextMenu 共 20+ 处）。
- 改动面：全量重皮 ≈117 个 .vue；最大风险是 scripts/tests/ 17 个源码文本守卫 + table.ts/columns.ts 类字符串契约 + CSP/xterm 链路。

### 5.3 视觉一句话画像

**应用界面是一套纪律严格但「小字海洋+无动效层级」的工具灰；桌面外壳是一套度量精确复刻 CoolDesktop 的玻璃拟态深色皮，两套皮靠「壁纸之上/之下」一条语义线切分，切分线以内精致、以外克制。**

## 10. 与成熟 NAS 桌面（fnOS 类）的差距分析

### 短板一：桌面「操作系统感」的深度不足（窗口系统是单层玩具级）

- 只有右下角一个缩放握把（无四边/八边缩放）、无窗口吸附/分屏、无多工作区/虚拟桌面、无任务栏窗口预览（hover 缩略图）、无快捷键体系（无 Win 键开启动器、无 Alt-Tab、无桌面快捷键）、窗口几何不记忆（重开归位）、启动器无搜索/分组/最近使用。fnOS 类产品这些都是标配。
- 证据：WorkbenchWindow.vue 只有 grip；windows.ts 无持久化；三期计划 §八 主动排除吸附/多桌面。

### 短板二：桌面没有「全局层」——壁纸、文件、通知、搜索都各自为政

- 壁纸仅 4 款硬编码渐变（应用壳层的自定义背景图能力没有接到桌面）；桌面不收文件拖放（terminals.ts 明确排除）；无全局搜索/命令面板（应用有 commands/batch 等能力但没有桌面入口）；无通知中心（传输完成只有 toast）；「传输」窗口只是应用级面板的搬运。
- 证据：WorkbenchPane `:150-155`；terminals.ts `:1644-1654`；TransferPanel 直载。

### 短板三：视觉双轨与基础件缺位放大了「两套皮」的割裂（报告结论在桌面域同样成立）

- 桌面 chrome 20+ 处内联 hex 半透明色完全绕开 token 体系，换肤/做亮色桌面不可能；桌面外应用界面 text-xs/11px 小字海洋、无 Button/Input/Tabs 基础件、无动效 token——fnOS 的图标/字牌/菜单是成套设计资产，本仓是「lucide 线条+彩色底片」的程序化贴纸。
- 系统面板/回收站等窗口内容仍是「表格+小字」的 SSH 工具风，与桌面外壳的玻璃风在同一窗口里形成两种时代感。
- 证据：视觉盘点报告 TOP10；ContextMenu teal 与主题卡两套菜单皮。

### 次级差距（补清单用）

- 无锁屏/登出/待机语义（电源只有重启/关机）；无多用户/账户切换语义；图标无徽标（回收站满/传输进行中不反映在图标上）；回收站无「在文件浏览器中打开」；Docker 窗口外无系统负载挂件（监控是独立窗口，任务栏不显示 CPU/内存）。
