# 界面视觉现状盘点调研报告

日期：2026-11-18
范围：apps/desktop/src 前端全部 UI（Vue 3 + Tailwind CSS 4 + reka-ui + @lucide/vue），双宿主 Tauri 桌面 + sevenshell-web 浏览器宿主共用同一套前端。
方法：只读盘点。逐文件读样式入口与基础件，rg 统计全仓 class 用量，交叉核对 docs/ui-conventions.md、docs/architecture.md、docs/security-model.md 与测试脚本。所有数字均带 文件:行号 或统计口径出处。

## 结论速览

1. **这不是「没有设计系统」的仓，恰恰相反——token 层是全仓最规范的部分**：Tailwind 4 CSS-first、单一 globals.css（989 行）、全部颜色 oklch、12 套界面配色 + 自定义配色、radius 全部由单一 `--radius` 派生。「丑」的病灶不在 token 层，在应用层：密度、层级、动效、基础件缺位。
2. **字号分布严重失衡**：`text-xs` 585 次、`text-[11px]` 540 次（78 个文件）、`text-[10px]` 179 次、`text-sm` 仅 160 次；`text-base` 在 .vue 里出现 0 次。界面整体是「小字海洋」，层级感几乎全靠颜色而非字号——这是「看起来像工具灰」的第一大原因。
3. **没有 Button 组件**：431 个裸 `<button>` 散布在 91 个文件，无任何共享 class 常量；`"disabled:cursor-not-allowed disabled:opacity-60"` 这串复写出现 49 次（44 个文件），同一段按钮配方字符串重复 4~6 次的有十余种变体。cva 在 package.json 里声明了依赖却全仓 0 处使用。
4. **动效层近乎空白**：`transition-colors` 426 次是唯一的动效词汇；对话框/toast/下拉**没有任何进出场动画**（`animate-in`/`animate-out` 0 次，Vue `<Transition>` 用量极低），toast 是「啪一下出现」。时长 token 不存在：`duration-*` 全仓只有 3 次，缓动只写死 1 次 `ease-out`，globals.css 里两个手写 keyframes 各自带各自的 cubic-bezier。
5. **焦点可见性大面积缺失**：431 个裸 `<button>` 所在的 91 个文件中，仅 7 个文件含任何 `focus-visible`（且未必落在按钮上——已验证 Composer.vue:46 的 ring 只给了 textarea，其 3 个按钮在 :126/:137/:149 均无）；`outline-none` 出现 168 次。键盘用户在绝大部分按钮上没有可见焦点环。
6. **基础件覆盖面极窄**：components/ui/ 只有 8 个通用件（Select、Switch、ConfirmDialog、ColumnResizeHandle、SideDivider、SortHeader、FontSelect、SystemIcon）；无 Button、无 Input、无 Tabs、无 Tooltip、无 Popover、无 Skeleton、无 Badge。每个业务域（settings 32 个组件、k8s 17 个、container 12 个）各自手写对话框和按钮。
7. **个性化面很宽**：亮暗 + 跟随系统、12 套命名配色 + 5 色自定义配色、3 档圆角、2 套界面布局（classic/separated）、150+ 内置终端配色（schemes.ts 4781 行）、工作台壁纸 4 款 + 自定义背景图。这块是产品亮点，不是短板。
8. **硬编码颜色极少**（token 纪律好）：.vue 中 hex 颜色仅 3 个文件 14 处——AppMark 品牌图标 4 处、TerminalPane 透传 xterm 2 处、WorkbenchPane 壁纸渐变 8 处；`rgb()/hsl()` 0 处。换肤改动面小。
9. **测试与样式的耦合是「结构性耦合」而非「类名耦合」**：158 个 spec 断言 Tailwind 类名的仅 3 个文件 11 处（table.spec.ts、WorkspaceTabs.spec.ts、ColumnResizeHandle.spec.ts）；scripts/tests/ 下 17 个守卫测试（typography/tables/selection/vueTemplates/windowCsp 等）直接断言源码文本，改样式必然碰这些守卫；e2e 866 次 getByRole + 79 次 getByText，主要是角色/文案耦合，改文案比改样式更危险。
10. **CSP 硬约束确认**：`style-src 'self' 'unsafe-inline'` 是必须项且被 `scripts/tests/windowCsp.test.mjs:47-60` 守卫——xterm 的字体/字号/配色是一段 inline `<style>`，任何 nonce/hash 化改造都会静默弄死终端样式。
11. **xterm 不吃 oklch**：docs/architecture.md:144 明确；当前实现是 globals.css 用 oklch 定义 `--terminal-*`，再由 TerminalPane 在 JS 侧读取后转交浏览器（详见第 7 节），重构配色时必须保留这条「CSS 变量 → JS 读取 → xterm theme 对象」链路。
12. **改动面量级**：全量重皮 ≈ 117 个 .vue + 1 个 globals.css；若重皮按「保 token 层、重写应用层」走，主要工作量在 91 个含按钮文件的按钮统一、密度重排（text-xs → text-sm 的层级上移）和动效层从零补齐；最大风险点是 17 个样式守卫测试 + table.ts/columns.ts 这两份「类字符串即契约」的模块。

## 1. 样式基础设施

### 1.1 Tailwind 4 配置形态：CSS-first，无 JS config

- 入口 `apps/desktop/src/styles/globals.css:1` `@import "tailwindcss"`；`:3` `@custom-variant dark (&:where(.dark, .dark *))`——dark 变体是 class 策略（`.dark` 类挂在 html 上，index.html:2 初始 `class="dark"`）。
- 无 tailwind.config.js/ts（全仓未找到），一切 token 定义在 CSS `@theme` 块：`globals.css:741-781` 用 `@theme inline` 把 27 个语义色变量映射进 Tailwind 命名空间（`--color-background`、`--color-primary`…），radius 四档派生（`:774-777`，`calc(var(--radius) * 0.6/0.8/1/1.4)`），字体栈两枚（`:779-780`）。
- 构建侧 `@tailwindcss/vite ^4.3.0`（package.json devDependencies），无插件扩展。

### 1.2 颜色体系：oklch 全覆盖，语义 token 单一事实源

- `:root`（globals.css:16-87）声明基础亮主题：background/foreground/card/muted/border/input/primary/accent 五组前后景 + destructive/success/warning/info 四个语义色 + 7 个 completion 色 + ring/overlay。全部 oklch（除 overlay 带透明度）。
- `.dark`（globals.css:137-166）整套覆盖；12 套命名配色 `[data-palette="mist|graphite|cobalt|sage|amber|blush|vscode|idea|xcode|jetbrains|cursor|claude"]` 每套都同时给亮/暗两块（globals.css:193-671），另加 5 色自定义配色走运行时 inline token（stores/preferences.ts:732-743）。
- 文件级注释明确了配色规则：「palette 只动灰和 accent，不动语义色」（globals.css:184-190）。
- 终端色独立成 `--terminal-{dark,light}-*` 四表面（globals.css:70-77）+ `.terminal-dark/.terminal-light` 两个类各带 16 个 ANSI 色（globals.css:695-739），与界面主题解耦（注释 globals.css:673-694）。
- **结论：颜色不是短板**。硬编码 hex 全仓 .vue 仅 14 处（AppMark.vue:21-29 品牌图标 4 处、TerminalPane.vue:556/559 xterm overview ruler 透传 2 处、WorkbenchPane.vue:102-104 壁纸渐变 8 处），均有合理理由。

### 1.3 字体：栈已声明，但 Inter 没有被加载

- `--font-sans: Inter, "Segoe UI", system-ui, sans-serif`；`--font-mono: "JetBrains Mono", Consolas, ui-monospace, monospace`（globals.css:779-780）。
- **全仓没有任何字体文件**（apps/desktop 下 0 个 woff/ttf），index.html 无字体 preload/link，CSP `font-src 'self' data:`（src-tauri/tauri.conf.json:36）也说明字体只能来自打包资源。也就是说 Inter/JetBrains Mono 是「写在栈首位、实际永不命中」的名称，Windows 实际渲染是 Segoe UI/Consolas，浏览器宿主则取决于系统。这是「看起来普通」的直接原因之一：设计目标字体从未真正上屏。
- 字号层级（.vue 全量统计）：

| class | 次数 |
|---|---|
| text-xs | 585 |
| text-[11px] | 540（78 个文件）|
| text-[10px] | 179 |
| text-sm | 160 |
| text-base | 0 |

- ui-conventions.md:79-109 定义了「四档字号一个权重」的类型规范并声明 settings 页以 text-xs 为主是有意为之；typography.test.mjs（scripts/tests/typography.test.mjs）守卫 settings 页。但全局读数显示 11px/10px 的机器字已从「例外」变成与 text-xs 同量级的日常字体；`text-[10px]` 179 次的最大用户不是监控面板（MonitorPanel.vue 仅 10 处）而是 assistant 域（ServerContentDialog.vue 29 处、ContextPreview.vue 12 处）。
- 权重纪律执行良好：font-medium 233 次、font-semibold 仅 1 次、font-bold 0 次（符合 ui-conventions.md:97「nothing bolder than medium」）。

### 1.4 圆角/阴影/边框

- 圆角高度统一：`--radius` 单一源（globals.css:81）+ `[data-corner-style]` 三档用户偏好（globals.css:96-102）+ `.rounded` 工具类重定义为 `var(--radius-sm)`（globals.css:790-793，专门修 Tailwind 自带 rounded 不随 token 动的历史漂移）。用量：rounded-md 605、rounded-sm 120、rounded-lg 51、rounded-full 37、rounded 21。
- 阴影几乎没有体系：shadow-xl 38 次（主要是下拉/对话框一次性给）、shadow-sm 7、shadow-lg 7、shadow-md 3；无 elevation token。整体是「扁平边框风」，阴影只在浮层出现，这是有意的轻量风而非散乱。
- 边框统一走 `border-border` token（globals.css:25/146）。

### 1.5 散落硬编码检查

- `:style=` 内联样式 55 处（多为动态定位/宽度/壁纸背景，属合理用法）；`!important` 0 处；globals.css 之外无第二个全局样式文件。

### 3.2 密度现状

- 上述字号分布（585 text-xs + 540 text-[11px] + 179 text-[10px]）就是密度问题的量化：**绝大部分「一句话」信息被写在 11~12px 上**，text-sm 只有名字级 160 次。表格两档密度由 lib/table.ts:55-76 契约化（page=text-xs 12px、panel=text-[10px]）。

### 3.3 空态/加载态/错误态

- 空态：62 个组件文件含 empty 相关内容；表格空态由 lib/table.ts:52/65/74 契约化（空态是表格的一行）。HomeView 有快捷入口。空态文案齐全但视觉朴素（纯 text-muted-foreground 一行，无插画/图标构图）。

- 错误态：规范化程度高（destructive token + 顶部 backend failure 条 App.vue:592-608 + toast + 每面板 failure 块），但同是小字 + 10% 透明底的一条样式，无插画级/分级的错误呈现。

- 亮暗：`themeMode: "system" | "light" | "dark"`（stores/preferences.ts:165、611-614），class 切换 + index.html 预置暗色底避免闪白（index.html:9-13）。
- 配色：12 命名 + default 共 13 套 × 2 主题 + 自定义 5 色 × 2 主题（preferences.ts:296-300），选择器是 `[data-palette]` 属性，CSS 单文件集中定义。
- 圆角三档（preferences.ts:313-319 → globals.css:96-102）；界面布局两套 classic/separated（globals.css:104-135）。
- 终端配色：`terminalSchemeSource` 默认跟随界面主题，可独立指定亮/暗两套（preferences.ts:193-198、673-680）；内置 `TERMINAL_COLOR_SCHEMES` **150+ 套**（lib/terminal/schemes.ts:28，文件 4781 行；schemes.spec.ts:16 断言 >150），另有自定义配色导入（TerminalSchemeImportDialog.vue）。
- 工作台壁纸 4 款：aurora/dawn/forest 渐变 + plain（WorkbenchPane.vue:7、102-104），另有用户自定义背景图（shell/Wallpaper.vue + lib/settings/background）。
- 字体大小/密度**不可调**：preferences 里无 fontScale/密度字段——个性化宽（颜色/圆角/布局/壁纸），但字号密度一刀切，而默认档恰是全仓偏小的 text-xs。

## 5. 动效与微交互

- 统计：`transition` 词根 443 次，其中 `transition-colors` 426 次——**96% 的动效只有颜色渐变这一种**；transition-transform 5、opacity 4、transition-all 4、裸 transition 4。`duration-*` 仅 3 次、`ease-*` 仅 1 次，全靠 Tailwind 默认 150ms。
- **无进出场动画**：`animate-in/animate-out` 0 次；Vue `<Transition>`/`<TransitionGroup>` 在组件层用量极少（grep 各组件仅个别 overlay 使用）；ConfirmDialog、SessionDialog、Select 下拉、Toast 均为即时出现/消失。
- globals.css 里仅两个手写 keyframes：settings 搜索命中呼吸（globals.css:909-928）与行定位呼吸（globals.css:969-989），均带 prefers-reduced-motion 降级（:924-928、:984-989）——质量好但只服务两处。
- Divider 手柄 .panel-grip 有 140ms color/opacity 过渡（globals.css:950-952）。
- 结论：动效层「有纪律、没体系」——没有时长/缓动 token，没有入场/离场词汇，重点交互（tab 切换、对话框、toast、下拉）全部硬切。这与其说是丑，不如说是「生硬感」的主要来源。

## 6. 可访问性与一致性硬伤

- **焦点可见性**：91 个含裸 `<button>` 的文件中仅 7 个含任何 `focus-visible`（脚本比对 `grep -Fxf` 两份文件清单得出），且验证样本 Composer.vue 的 focus ring 落在 textarea（:46）而非其 3 个按钮（:126/:137/:149）；`outline-none` 168 次远多于 `focus-visible` 48 次——大量控件去掉了原生 outline 又没补 ring。Select/ConfirmDialog 等少数基础件是好的（Select.vue:160）。
- **对比度风险点**：text-muted-foreground 在小字号（11px/10px）上承担了大量正文职责；暗主题 `--border` 是 0.28~0.44 透明度的白（globals.css:146/224 等 12 套各自写），hairline 在暗色下依赖半透明叠加，若壁纸/自定义背景图介入对比度不可控。
- 图标一致性：size 双轨（`:size` 数值 10 档 + `size-*` class），同一组件内混用（WorkspaceTabs.vue:621-630 全部 `:size="12"`，:637 却用 `size-4` 网格按钮）。
- 中英文排版：i18n 只有 en/zh-CN 两语言（apps/desktop/src/i18n/locales/）；未见 CJK 专用行高/字重调整（font-sans 栈无 "Microsoft YaHei"/"PingFang SC"，中文回退到系统默认——在 Windows 上中文实际字体不可控）；文本长度差异靠 truncate 168 次 + flex min-w-0 兜底。
- 选中语义（可否选择文本）有罕见的成文规范与守卫（ui-conventions.md + scripts/tests/selection.test.mjs + globals.css:842-864 元素级实现），这是亮点。

## 7. 约束盘点（改 UI 必须绕开的坑）

1. **CSP**：`style-src 'self' 'unsafe-inline'` 是硬要求，src-tauri/tauri.conf.json:36-39；docs/security-model.md:318-322 说明 nonce/hash 会关掉 unsafe-inline；scripts/tests/windowCsp.test.mjs:47-60 三条断言守卫（必须有 style-src、必须含 unsafe-inline、不得有 nonce/hash）。**原因**：xterm 的字体/字号/配色是一段运行时 inline `<style>`。任何想收紧 CSP 的重构都会静默弄死终端。
2. **xterm 不解析 oklch**（docs/architecture.md:144）：终端 16 ANSI 色 + 4 表面色以 oklch 存在 CSS 变量里（globals.css:695-739），由 TerminalPane 在 JS 侧读出后喂给 xterm theme 对象；lib/terminal/palette.spec.ts 守卫「每个 palette 二十个色一个不能少」。改终端配色必须保住「CSS 变量 → JS 读取 → xterm」链路，不能直接把 oklch 字符串塞给 xterm。
3. **双宿主一致性**：sevenshell-web 与桌面共用同一 apps/desktop/src（docs/architecture.md:9），浏览器宿主无 Tauri IPC（runtime.ts isDesktopRuntime 分支，App.vue:481-486、522-531）。改窗口 chrome（TitleBar/WindowControls）时注意桌面专属行为要有浏览器降级。
4. **i18n 双语言长度差**：en/zh-CN 两份 locale；e2e 79 处 getByText、组件 spec 大量 toContain 文案断言——改文案比改类名更容易红测试；文案改动必须双语同批。
5. **样式守卫测试（17 个，scripts/tests/）**：typography.test.mjs（settings 页字号/权重上限）、tables.test.mjs（不许表外写表头/单元格/hover）、selection.test.mjs（可选中语义）、vueTemplates.test.mjs、windowCsp.test.mjs、architecture.test.mjs、frontendBoundary.test.mjs 等。它们断言**源码文本**，全量重皮会成片触碰；其中 tables.test.mjs 的存在意味着 lib/table.ts 的 class 字符串（lib/table.ts:55-76）是「契约即样式」——改值要同步改测试。
6. **spec 类名耦合面有限**：仅 3 个 spec 文件 11 处直接断言 Tailwind 类（components/ui/ColumnResizeHandle.spec.ts、components/workspace/WorkspaceTabs.spec.ts、lib/table.spec.ts），另 10 个 spec 用 classList 做选中语义检查——纯视觉 class 改名大概率不红单测，但会红 scripts/tests 守卫。
7. **个人偏好属性链**：`[data-palette]`/`.dark`/`[data-corner-style]`/`[data-app-layout]`/`.terminal-{dark,light}` 是文档属性驱动的级联，globals.css 里 palette 块刻意排在 `.dark` 之后靠顺序取胜（globals.css:187-191 注释）——重排文件顺序会引入「暗色忘了覆盖」的静默 bug。

## 8. 结论

### 视觉短板 TOP10

| # | 现象 | 证据 | 影响 |
|---|---|---|---|
| 1 | 目标字体从未上屏，实际渲染系统默认字 | font-sans 首位 Inter 但全仓 0 字体文件、无 preload（globals.css:779、index.html 无 link、font 文件搜索为空） | 「原生工具感」的第一来源；中文栈完全未定义 |
| 2 | 小字海洋，无字号层级 | text-xs 585 + text-[11px] 540 + text-[10px] 179 vs text-sm 160、text-base 0 | 页面无视觉锚点，层级全靠灰度，整体发灰、发平 |
| 3 | 没有按钮组件，样式复制粘贴 | 431 个裸 button/91 文件；同配方字符串重复 4~6 次 ×十余种；cva 依赖闲置 | 视觉不一致的直接温床；任何全局按钮改款都是 91 文件的手术 |
| 4 | 动效体系缺位，重点交互硬切 | transition-colors 426/443；animate-in/out 0；duration 3 次；toast/dialog/select 无进出动画 | 「生硬感」；与现代化观感差距最大的一块 |
| 5 | 键盘焦点不可见 | 91 个含按钮文件仅 7 个含 focus-visible（且未必在按钮上）；outline-none 168 | 可访问性硬伤，也是「精致度」的直观减分项 |
| 6 | 图标尺寸双轨无规范 | `:size` 10 档（9~20）+ size-* class 并行 | 细节参差，密度感受不统一 |
| 7 | 加载态只有转圈 | 39 文件 animate-spin，skeleton/pulse 仅 7 处 | 等待体验原始；空态/错误态同样朴素 |
| 8 | 阴影无 elevation 体系 | shadow-xl 38 次集中在浮层，sm/md/lg 共 17 次 | 浮层与平面的纵深关系全靠 1px 边框，层次感弱 |
| 9 | 信息密度无用户出口 | preferences 无字号/密度调节字段 | 「嫌小的人」只能换配色，无法放大 |
| 10 | 中文排版零适配 | font-sans 无 CJK 字体；无 zh 行高/字距规则 | zh-CN 宿主下观感进一步打折 |

### 改动面评估

- **文件量级**：全量重皮 = 117 个 .vue + globals.css + index.html。若走「token 层保留、应用层重写」的路线（推荐）：
  - 必改：globals.css（补动效/阴影/字号 token + 字体打包）、新增 ui/Button/Input/Tabs/Tooltip/Skeleton 一批基础件（约 +8~12 文件）、index.html 字体加载；
  - 波及：91 个含按钮文件统一换 Button、585 处 text-xs 所在的约 90 个文件做层级上移、动效补齐约 30 个对话框/浮层文件；
  - 双语 locale + e2e getByText 的文案面不在视觉改动内但同批风险最高。
- **风险最高耦合点**：① scripts/tests/ 17 个守卫（尤其 tables/typography/selection/windowCsp，属「改样式必红」）；② lib/table.ts:55-76 与 lib/columns.ts 的类字符串契约；③ globals.css 的级联顺序（palette 块必须在 .dark 后）；④ CSP/xterm oklch 两条终端链路；⑤ `rounded` 工具类已被重定义（globals.css:790-793），全局换 radius 语义会隐性影响 21 处 `rounded`。
- **建议的主攻顺序**（供主控参考）：字体加载 + 字号层级上移（1/2）→ Button/Input 基础件（3）→ 动效 token + 关键路径进出动画（4）→ focus-visible 全量补齐（5）→ 图标尺寸规范（6）。前两项对观感改善的性价比最高，且都不触碰守卫测试的断言文本。
