## 结论速览

1. **产品身份**：GMSSH 对外名称是「极目Linux桌面」（GMSSH.exe VersionInfo ProductName 即此），版本 2.0.8.89；更新走阿里云 OSS（`https://gmb-prod-gw.oss-accelerate.aliyuncs.com/client/win/x64/`），配套云端 api.gm.cn / web.gm.cn / api.gmssh.com，文档站 doc.gmssh.com。
2. **Electron 只是壳**：主进程 861KB 的 `dist-electron/main.js` 里 `ssh2` / `node-pty` / `WebSocket` / `safeStorage` / `keytar` 出现次数全为 0（grep 实证）——SSH 完全不在 Electron/Node 里实现。
3. **真正的 SSH 引擎是三个本地 Go sidecar 进程**：主进程从 `%APPDATA%\GMSSH\serve\` 启动 `gs_main_win_x64.exe`（GMServer，默认端口 21789）、`gmb_multi_server_win_x64.exe`（多机服务，终端 WebSocket）、`browser-app-win_x64.exe`（+ 自带 node.exe 与 playwright-core，服务器浏览器）。二进制不打包进安装目录，而是按资源版本独立下载更新（gs/ga/gc/web/new_web/browser/appcenter/client_server 八个组件）。
4. **GMServer 用 `golang.org/x/crypto/ssh` 实现完整 SSH 栈**：口令/私钥/证书认证、knownhosts 严格校验、SFTP（SSH_FXP_* 包名实证）、跳板机链、代理、以及 `purposetunnel` 隧道管理（gs_main 二进制函数名可读，未 strip）。
5. **远程侧还有一个 GA agent**：连接主机时自动在远端部署 `ga_main_x86/arm` 到 `/.__gmssh/`（配置实证：jrpc over unix socket、socks5、data/desktop/plugin/tmp/Recycle_bin 目录），GMServer 经 SSH 通道连接 GA（二进制字符串 `dial GA agent through %s SSH connection` 实证）。GA 用 UPX 4.24 加壳，静态分析受限。
6. **「Linux 桌面」不是像素流远程桌面**：全量语言文件 833 键与二进制指纹中无 VNC/noVNC/RDP/X11 抓屏/H264/WebRTC 任何痕迹；它是本地 GMServer 托管的 **Web 桌面 SPA**（`http://127.0.0.1:{gmPort}/newweb/#?...`），Electron 用 `<webview>` 内嵌渲染，以桌面隐喻（壁纸/桌面图标/回收站/应用中心/任务管理器）操作远端文件系统与系统，数据经 SSH→GA agent 取回。
7. **额外的"真"远程可视化**是「服务器浏览器」：本地 playwright-core 驱动 Chrome/Edge，经 browserPort 的 `/api/browser/proxy_open_stream` 代理打开远端上下文的 Web 页面（进入需远端 root/sudo 授权，推断：页面流经 SSH 隧道代理）。
8. **终端**走多机服务的 WebSocket：`ws://127.0.0.1:{multiPort}/terminal/{id}`，前端 xterm.js 6（`@xterm/xterm` + webgl/search/fit addon），自动重连 9999 次。
9. **端口转发是产品级功能**，四类型：本地转发、远程转发、动态转发（SOCKS5）、远程中转转发（经服务器访问其内网任意 IP:port），REST API `/tunnel/add|edit|list|start|stop|validateTunnelPorts`；远端 sshd 未开 AllowTcpForwarding 时 GMServer 会**自动改写远端 sshd_config**（含备份/语法校验/恢复，支持 OpenSSH 与 Dropbear——这是行为激进点）。
10. **凭据安全是分层的**：机器凭据由 GMServer 落盘 `credential.json`（AES 加密文件存储，`gmb-server/pkg/credential/encrypted.NewAesEncrypted` 实证），可选「机器仓库密码保护」；云同步是零知识方案（本地 AES-256 加密后上传，仓库密码不传云端，遗忘只能清空仓库）；登录密码用内嵌 RSA 公钥加密上传；桌面/终端会话用短期 token（encryptedData/encryptedNum 挑战应答）。
11. **商业模型**：普通用户/授权用户/永久授权用户三档 + 官方体验服务器（云端临时容器 `web.gm.cn/api/v1/user/gen_container`）；机器云同步、AI 配额都挂在授权码体系上。
12. **内置 AI 助手（GMAI）深度绑定产品**：AI 生成命令需用户确认执行（终端内嵌确认条）、知识库/技能市场/提示词/模型服务商管理全在 GMServer 侧，出口走官方网关 `api.gmssh.com/api/ai_gmai_v3/chat`（账号 JWT 鉴权，无本地静态 sk- 密钥——与 `_analysis/GMSSH_AI_逆向分析.md` 结论一致）。

## 二、技术栈与打包方式

**asar 顶层结构**（解包于 F:\tmp\7shell-research\gmssh-asar）：

```
package.json            name=GMSSH, version=2.0.8, type=module, main=dist-electron/main.js
dist/                   renderer（Vite 多页：index.html 主界面 + terminal.html 终端页）
dist-electron/          main.js(861KB) / preload.js / webview-preload.js / resource-worker.js
node_modules/           仅 electron-log、electron-store(8)、electron-updater 三个运行时依赖
```

**前端栈**（`package.json` dependencies，13-53 行）：Vue 3.5 + vue-router + pinia + vue-i18n；UI 双库并存 `@arco-design/web-vue` 与 `naive-ui`（主界面用 Arco，Web 桌面用 naive-ui）；xterm 6（`@xterm/xterm` + addon-fit/search/webgl）；tailwindcss 4；md-editor-v3 + katex + mermaid + highlight.js（AI markdown 渲染，mermaid 各图型 chunk 独立分包）；crypto-js 4.2.0、jsencrypt、jsrsasign（凭据/通道加密）；electron-store 8（主进程配置）。

**构建方式**：Vite 多页打包（产物文件名带内容 hash，如 `index-DirkJJF0.js`、`terminal-BDXfTJmJ.js` 4.2MB），主进程同样被 Vite/rollup 打成单文件 ESM。**应用自身无 sourcemap**——仓库里的 32 个 .js.map 全部来自 `node_modules/electron-updater` 自带产物，业务代码只有压缩后的 JS（esbuild 保留了中国注释行，可读性尚可）。

**进程与窗口模型**（`dist-electron/main.js`）：

- 主窗口（main.js:23515）：1440x900、frame:false、`titleBarStyle: "hiddenInset"`，**`nodeIntegration: true` + `webviewTag: true`**（主进程信任自家 renderer 的写法，与极简 preload 桥配合）。
- 隐藏窗口 browser.html（main.js:20180）：承载服务器浏览器相关能力，同样 webviewTag 开启。
- 多标签页架构：每个「桌面/终端」标签是一个 `<webview>`，guest 页分别加载 terminal.html 或桌面 URL；`webview-preload.js` 提供 host 消息桥（`message-from-webview`/`render-to-webview`）、Ctrl+Tab/Ctrl+1~9 快速切签（状态存 localStorage `gmssh-quick-change-tab`）、设置同步（`webview-setting-sync`）与禁缩放/禁刷新守卫。
- **IPC 面极度收敛**：preload.js 只暴露 `render-to-main`（invoke 白名单）与 `main-to-render`（推送白名单）两个通用通道 + `skillDownload` + `networkStatus` + `electronParam`。main.js:23190 起的 `render-to-main` switch 分发约 30 个子命令（check-update、resource-start-update、multi-server-restart、set-gm-cookie、handle-file、show-item-in-folder、set-app-exit-to-tray 等）；main.js:23461 起的 `webview-to-main` 提供 `get-port`、`startGMServer`、`restart-browser-server`、`show-context-menu` 等。
- **resource-worker.js**（28KB）：worker_threads 里的 ZIP 解包器（node-stream-zip 逻辑内联），供资源更新事务在子线程解压八个组件。
- **资源独立更新体系**：`config.json`（electron-store）记录 resourceVersions `{gs, ga, gc, web, new_web, browser, appcenter, client_server}`，更新走「下载→worker 解压→停 sidecar→替换→重启」事务（userData 下 `.temp-update`/`.resource-update-*` 状态目录）。也就是说 Electron 壳版本与 SSH 引擎/桌面前端版本是**两条升级线**。

## 三、SSH 实现方式

### 3.1 排除法：Electron 侧无任何 SSH 实现

对 `dist-electron/main.js`（主进程全部代码）grep 实证：`ssh2`=0、`node-pty`=0、`WebSocket`=0、`safeStorage`=0、`keytar`=0。renderer 各 bundle 亦无 ssh2 特征串。resources 目录也没有 `app.asar.unpacked`（原生模块不在 asar 外）。

### 3.2 实证：本地 Go sidecar 承担全部 SSH

main.js:7251-7287 的平台分发表给出三个 sidecar 的可执行文件名：

```
win32:  gs_main_win_<arch>.exe / gmb_multi_server_win_<arch>.exe / browser-app-win-<arch>.exe
darwin: gs_main_mac_<arch>    / gmb_multi_server_mac_<arch>    / browser-app-darwin-<arch>
linux:  gs_main_linux         / gmb_multi_server_linux         / browser_app
```

main.js:22540-22600 展示 GMServer 的启动协议：工作目录 `userData/serve/app`，命令行参数 `["http", String(port)]`，stdout 中 `port=(\d+)` 作为就绪信号，默认端口 21789（main.js:22517），端口被占则自动换端口并把实际端口回写 config.json。本机 userData 已落盘全部三个二进制：

```
%APPDATA%\GMSSH\serve\app\gs\bin\gs_main_win_x64.exe          60.8MB  GMServer（本地主服务）
%APPDATA%\GMSSH\serve\multi\gmb_multi_server_win_x64.exe       7.7MB  多机服务（终端 WS、机器状态推送）
%APPDATA%\GMSSH\serve\browser\browser-app-win-x64.exe                 服务器浏览器服务
%APPDATA%\GMSSH\serve\browser\helper\node\node.exe + playwright-core  浏览器自动化运行时
```

gs_main 为 Go 编译、未 strip（pclntab 全量函数名可读），包结构自证：

```
gmb-server/internal/sshmanager{,/lib,/purposetunnel}   SSH 连接与隧道管理
gmb-server/internal/api/{terminal,files,socks,mfa,user,transfer,logs,static,version,initialization,...}
gmb-server/internal/initialization/{sshdconfig,sshforwarding}
gmb-server/internal/terminal/{session,compat}
gmb-server/internal/transferapp/{access,admission,checkpoint,feed,ga,identity,paste,progress,retry,...}  服务器对传
gmb-server/pkg/credential/{storage,encrypted,entity}   凭据加密存储
```

SSH 协议能力（gs_main 字符串实证）：认证支持口令、私钥（含 bcrypt_pbkdf 加密私钥）、CertificateAuth（证书+CA）、keyboard-interactive、SSH_AUTH_SOCK 代理转发；KEX 含 MLKEM768-P256 混合后量子算法（`ssh.mlkem768WithCurve25519sha256`）；MAC hmac-sha2-256/512；加密含 chacha20-poly1305；knownhosts 严格校验（`knownhosts: key is unknown/revoked`）；SFTP 完整实现（SSH_FXP_LSTAT/FSTAT/MKDIR/RMDIR/ATTRS/CLOSE/WRITE、statvfs@openssh.com 扩展）。跳板机链有专门错误串（`failed to connect jump host` / `failed to connect target through jump hosts`），HTTP/SOCKS 代理在 `internal/api/socks` 与 `entity.ProxyConfig`。

### 3.3 远端 GA agent：SSH 之上的「第二协议层」

gs_main 中字符串 `dial GA agent through %s SSH connection: %w`、`VerifyTcpForwarding`、`GA HTTP %s %s: dial failed` 实证：GMServer 在 SSH 连接建立后，会经 SSH 通道连接远端的 GA agent（GMSSH-Agent），后续文件/系统操作走 GA 的 JSON-RPC。

GA 侧配置（本机落盘 `%APPDATA%\GMSSH\serve\app\gs\ga\config.json`）：

- 远端工作根目录 `/.__gmssh/`，启动目录树 `cache,data,desktop,logs,plugin,script,tmp`，回收站 `/.__gmssh/.Recycle_bin`；
- IPC 用 unix domain socket `/.__gmssh/tmp/rpc.sock`（jrpc）；
- GA 自带 socks5 能力（`"socks5": true`）；
- GA 分发地址 `https://api.gmssh.com/api/package_ga/lastest`（gs_main 内实证），主进程侧语言串「GMSSH-Agent 自动启动」「upload agent file...」与 GMServer 函数 `agent.NewInvocation` 等表明首次连接会自动上传并拉起 GA；
- GA 对应插件体系 `/.__gmssh/plugin/{vendor}/{app}`（如 official/mysql、official/php），配套 install_server.sh、php_extensions.sh 等脚本（gs_main 内嵌脚本串实证）；
- GA 二进制（ga_main_x86 6.4MB）为 **UPX 4.24 加壳** ELF，静态字符串几乎全不可读，仅尾部 SAFE_META 构建戳（`commitId 25326df, zack, 2026-11-10`）。

### 3.4 终端数据面

Electron 侧终端页（terminal.html + `dist/assets/terminal-BDXfTJmJ.js` 4.2MB）用 xterm.js 6 渲染，数据通道是多机服务的本地 WebSocket：`ws://127.0.0.1:${serverPorts.multiPort}/terminal/${sessionId}`，带 `autoReconnect:{retries:9999,delay:1000}`（terminal bundle 实证字符串）。协议含 ping/pong/resize 帧。PTY 生成在 Go 侧（gs_main `session.PTYSession/PTYHandler`），Node 进程只做转发。

（推断，标注）：`internal/terminal/compat` 暗示对旧 SSH 服务器的兼容层（如不支持 exec 的场景降级 shell）。

## 四、远程桌面与可视化能力

### 4.1 判定：「Linux 桌面」= Web 桌面（desktop-metaphor over SSH），非像素流

三层证据链：

1. **指纹排除**：全部 JS 产物、833 键语言文件、未加壳的 gs_main 二进制中，VNC/noVNC/websockify/guacamole/Xvfb/xrdp/x11grab/MJPEG/H264/H265/WebRTC/screego 计数全为 0（gs_main 里 27 处 "rdp" 命中经查为 Go 运行时其他单词的子串假阳性）。index.html 标题虽叫「极目Linux桌面」，但桌面本体不传屏幕像素。
2. **URL 实证**（`dist/assets/index-DirkJJF0.js` 的桌面 URL 构造函数 `Ri`）：打开桌面即构造本地 URL 并塞进 webview——

```
http://127.0.0.1:{gmPort}/newweb/#/?machineId=..&host=..&user=..&serverAlias=..
    &site=..&lang=..&embeddedClient=1&encryptedData=<会话token>&encryptedNum=<随机数>
```

（preAuth 场景走 `/home` 路径）。桌面 UI 由**本地 GMServer** 提供（本机落盘 `%APPDATA%\GMSSH\serve\app\gs\new_www\`，Vite 产物，Vue3+naive-ui+ace-editor，含 wallpaper 目录），文件/系统操作由 GMServer 经 SSH→GA agent 落到远端执行。
3. **语言文件全貌**（`serve/app/gs/bin/resources/lang/zh-CN.json`，833 键）枚举出的桌面功能全部是文件/系统/应用级操作：桌面图标与位置、回收站、快捷方式、应用中心、任务管理器、文件管理器、磁盘管理、网络挂载、系统设置、AI——没有一项是屏幕流。

### 4.2 Web 桌面功能清单（实证 API 面，出自 `%APPDATA%\GMSSH\serve\app\gs\www\assets\*.js`）

- 文件管理：`/api/files/get_dir、create_dir、delete_dir、mv_file、copy_file、zip、un_zip、read_file_body、write_file_body`（大文件只读写首尾 1M——versions.json 变更日志实证该策略）、batch_paste、remote_download、get/set_file_access、get_path_size、以及 **SVN checkout/update/cleanup**（面板直接集成 SVN）
- 回收站：get/set_recycle_status、recovery_files、recovery_all_files、flush_recycle
- 桌面：add_shortcuts、move_desktop、desktop_rename、quick_visits、桌面分组
- 系统：process_list、kill_process、sessions、disk_list、get/set_dns、calibration_time、startup_list、get_swap、memory_disk（内存盘）、load_status
- 应用中心：app_install、app_upgrade、app_main/list2/search_lenovo（商店+联想搜索）、favorites
- 命令库：cmd_main/list_cmd/list_group（终端常用命令知识库，即 terminal bundle 内 ~900 条中文命令释义的数据源）
- 服务器对传：/api/transfer/chunks、upload_file_info、check_exists_files、cancel——两台远端机器互传，暂停/续传/重试/断点，冲突可选覆盖（gs_main `transferapp` 子包 checkpoint/admission/retry/identity 与之对应）
- 网络存储挂载：NFS/SMB/WebDAV 三协议挂到远端文件系统（错误串精确到 nfs-common、cifs-utils、davfs2.conf、/etc/davfs2/secrets——实现方式是**在远端装客户端**后经 GA 挂载）
- 磁盘管理：parted 分区、ext4/xfs 格式化、gdisk/cloud-guest-utils 扩容、挂载/卸载
- 账户：user_auth/register/login/reset_password（Web 桌面自身有注册体系）、/api/v1/mfa/*（MFA 动态密码）
- AI：/api/home_ai/start_session、chat、knowledge、skills、providers、prompts（见结论速览第 12 条）

### 4.3 服务器浏览器（真正的远程可视化补充）

除桌面外唯一带「远程界面」性质的功能。实证链：本地 sidecar `serve/browser/browser-app-win-x64.exe` + 自带 `node.exe` + **playwright-core**（目录枚举）；renderer 请求 `http://127.0.0.1:{browserPort}/api/browser/proxy_open_stream?...`（machine-manage bundle 实证）；UI 串「进入服务器浏览器需要root权限，请输入sudo密码」「目前只支持通过 Chrome 或 Edge 浏览器访问」「正在启动服务器浏览器」；main.js 有 per-machine 的 browserDownloadManager（下载历史、在文件夹中显示）与 webview-to-main 的 `restart-browser-server`（该服务默认关闭、按需启动）。

（推断，标注）：形态大概率是本地 playwright 驱动用户本机 Chrome/Edge，页面请求经 browserPort 代理走 SSH 隧道从远端出口访问（用于操作远端机器/内网的 Web 服务），页面流以 proxy stream 方式呈现并纳入下载管理；具体流协议（CDP 反代 or HTTP 代理）静态产物未能确证。

### 4.4 资源监控

机器级 CPU/内存/网络监控由多机服务推送（UI 串「解析机器状态推送失败」「轮询刷新机器 WS 信息失败」实证），Web 桌面内另有 `/api/system/load_status` 与任务管理器（含上传/下载速度单位自动切换 b/kB/MB——versions.json 实证）。Electron 侧不做任何监控计算。

## 五、SSH 隧道与端口转发

### 5.1 四种转发类型的 UI 配置模型（machine-manage bundle 中文串逐条实证）

| 类型 | UI 文案定位 | 表单字段 | 实现对应 |
|---|---|---|---|
| 本地转发 | 把服务器里的服务映射到本地访问 | 本地监听端口、服务器内端口 | SSH -L（gs_main `ssh.forwardedStreamLocalPayload`） |
| 远程转发 | 让别人通过服务器访问你的本地服务 | 服务器监听端口、本地端口、允许公网/外部网络访问（非 root 端口需 >1024） | SSH -R；开启公网访问需远端 sudo（对应 sshd GatewayPorts） |
| 动态转发 | 本地 SOCKS5 代理走服务器出口 | 本地代理端口、允许局域网访问 | SSH -D；Web 桌面另有 `/api/v1/socks/start、stop` 独立开关 |
| 远程中转转发 | 通过当前 SSH 服务器访问其内网中其他主机 | 本地端口、待访问 IP 地址、端口 | SSH -L 到任意 host:port（经服务器 direct-tcpip 中转） |

每类都内置场景示例文案（本地 Navicat 连 127.0.0.1:3306 实际访问服务器 MySQL；经 A 中转访问内网 B 的 10.0.0.8:80 等），是面向小白的解释式 UX。

### 5.2 隧道生命周期与 API

REST 面（共享 chunk `vue3-context-menu-BUnaRgAC.js` 内 API 定义实证）：`/tunnel/add、/tunnel/edit、/tunnel/delete、/tunnel/list（按 nodeId）、/tunnel/start、/tunnel/stop、/tunnel/updateName、/tunnel/validateTunnelPorts`（创建前端口占用校验，「端口已被占用」）。隧道按机器组织，字段含 type、port、allowPublicNetwork 等；独立隧道列表 UI（状态/启停/编辑/删除）+ 独立状态 WebSocket（「隧道状态 WebSocket 重连失败」）。gs_main 的 `session.Tunnel/TunnelInfo`、`tunnel.ConnectionFactory/ManagedConnection`、`purposetunnel.Lease` 表明连接池化复用、按用途（purpose）分租约。

衍生用法：`/tunnel/api/files/get_dir`、`/tunnel/api/transfer/*` 说明文件浏览与对传也能**经隧道指向第二台机器**——隧道不只是端口映射，还是产品内部跨机数据面的路由方式。

### 5.3 激进行为：自动改写远端 sshd_config

gs_main 存在 `internal/initialization/sshdconfig` 与 `sshforwarding` 包，错误串覆盖完整事务链：`tcp forwarding configuration failed: backup failed / syntax validation failed / restore failed / current sshd_config is invalid / unsupported SSH server / unable to inspect Dropbear state`。语言文件对应文案：「检测到您的SSH没有开启端口转发功能，登录GMSSH桌面可解决此问题，是否前往？」。即：**目标主机未开 AllowTcpForwarding 时，客户端会自动（带备份/语法校验/失败回滚）修改远端 OpenSSH 或 Dropbear 配置并重启 sshd**，以打通 GA agent 依赖的转发能力。这对目标主机有侵入性，7shell 借鉴时应视为反面教材，至少做成显式授权项。

## 七、安全模型（凭据存储）

1. **机器凭据（SSH 口令/私钥）不在 Electron 侧存储**（electron-store 的 config.json 无凭据字段），全部交给 GMServer：落盘 `%APPDATA%\GMSSH\serve\app\credential.json`，键为 32 位 hex（疑似凭据 ID 摘要），值为约 876~880 字符密文。gs bin config.json 明示 `"credential": {"storage_type": "encrypt", "position": "credential.json"}`；gs_main 符号 `gmb-server/pkg/credential/storage.NewEncryptFileStorage`、`encrypted.NewAesEncrypted`、`storage.(*EncryptFileStorage).decrypt` 实证 AES 加密文件存储。解密密钥来源未完全实证（语言文件有「get secret failed」，Electron config.json 有 `keyStatus.hasInit`——推断：首次启动生成密钥并由客户端保存，开启仓库密码后再叠加用户密钥派生）。
2. **可选机器仓库密码保护**：「已经设置机器仓库加密，每次启动软件需要使用此密钥查看机器信息」。
3. **云同步零知识**：见 6.4；仓库密码遗忘只能清空云端仓库重来（UI 有强确认文案）。
4. **登录链路**：系统浏览器 OAuth 式回调（「官网回调参数/地址」日志标签、默认浏览器检测文案）；initAuth bundle 内嵌 pro/dev 两对 RSA-2048 PEM——公钥配合 `encryptUnicodeLong` 分块加密长文本上传，私钥用于解密云端下发数据。**两把私钥都打包在客户端内**，属可提取的共享机密（与云同步零知识形成对比：登录通道不是零知识）。
5. **本地会话鉴权**：renderer→GMServer 走挑战应答（本地服务发 encryptedData+encryptedNum → 回传校验 ack-1）+ 短期 token/refreshToken（desktopSessionTokens 含过期时间，失效走恢复流）。远端敏感操作有独立 sudo 校验流（`/api/v1/user/sudo_auth`、sudo 密码单独保存、gs_main 内嵌 `__GMAI_SUDO_PROMPT_` 探针与 `printf '%s\n' %s | sudo -S -p '' sh -c %s` 模式）。
6. **Electron 防护姿态**：preload 白名单双通道很克制，但主窗口 `nodeIntegration: true` + `webviewTag: true`（main.js:23515 实证），renderer 被攻破即等价本地 Node 权限；webview 加载的是本地 GMServer 页面，信任边界依赖 127.0.0.1 服务的鉴权。
7. **MFA**：`/api/v1/mfa/create_mfa、activate_mfa、verify_mfa、delete_mfa、list_mfa`，连接可要求二次验证（动态密码 6 位，TOTP 类，推断）。
8. **明文面**：未发现 SSH 凭据明文落盘路径；日志侧有 safelog 包、hooks.secret（webhook 签名）、可选登录日志与钉钉告警（gs bin config.json 实证）。

## 八、对 7shell 的可借鉴清单

**架构层**

1. **Electron 壳 + 本地 Go 服务双进程架构**：SSH/PTY/SFTP 引擎独立于 UI 进程，升级互不阻塞（GMSSH 的八组件资源版本表 + 独立下载替换事务）。7shell 是 Rust/Tauri，等价物是「核心能力下沉到独立 Rust 服务进程或 CLI sidecar」，收益是 UI 崩溃不杀会话、引擎可单独灰度。
2. **IPC 面白名单化**：GMSSH 的 preload 只放行两个通用消息通道 + 少量具名 API，所有能力子命令走 type 分发，审计面极小。7shell 的 Tauri command 面可对照收敛。
3. **本地服务就绪协议值得抄**：sidecar 参数传期望端口、stdout 打印 `port=<n>` 作为就绪信号、端口被占自动换端口并回写配置——简单可靠，且主进程全程跟踪进程退出码区分「planned-restart/abnormal-exit」。
4. **resource-worker 在子线程做解包**：更新事务（下载→解压→停服→替换→重启）不卡 UI 线程，且有 `.resource-update-*` 状态目录支持断点续跑。

**功能层**

5. **隧道按「场景示例」做四类型 UI**：每种转发配一句「你想做什么」+ 具体端口示例文案，比裸露的 -L/-R/-D 参数表单易懂；`/tunnel/validateTunnelPorts` 创建前预检端口占用也是好体验。
6. **Web 桌面（桌面隐喻的文件/系统面板）**是「Linux 桌面」需求的低成本解法：壁纸+图标+回收站+应用中心全用前端画，数据走 SSH 取远端真实文件系统——不需要 VNC/GPU 流。7shell 若做「Linux 桌面」页签，这条路线比像素流便宜一个数量级，且对无桌面的无头服务器同样可用。
7. **服务器对传**（两台远端机器互传、断点/校验/冲突策略）是差异化功能，GA/GMServer 双侧配合实现；7shell 可先做「经本地中转」的简化版（源→本地→目标）。
8. **网络存储挂载三协议**（NFS/SMB/WebDAV）落在远端装客户端 + GA 挂载，把「文件管理器里看挂载盘」做成产品能力。
9. **终端命令知识库**：~900 条常用命令的中文释义/示例做联想输入，数据源就是一份 JSON；7shell 的 AI 气泡可复用其结构做离线联想兜底。
10. **连接体验细节**：批量添加的「每行一台」文本格式 + 先测试再导入失败机器；代理与跳板机互斥的二次确认；重启机器要求输入「确认重启」；连接时自动回读 OS 名填充卡片。

**安全层**

11. **凭据本地加密落盘 + 可选仓库密码**：AES 加密文件 + 启动口令二态（关=绑定机器的密钥，开=用户密钥派生）。7shell 可用 Tauri stronghold/keyring 实现同层级，优于 GMSSH 之处是可以直接用 OS keychain 而不必自管密钥文件。
12. **零知识云同步**是同步方案的正确形态（本地加密、云端不可解、遗忘即清空），值得作为 7shell 未来同步功能的设计基线；反面参照是它登录通道内嵌可提取的 RSA 私钥。
13. **反面教材两则**：a) 自动改写远端 sshd_config 开 AllowTcpForwarding（即便带备份回滚也越权）；b) 主窗口 nodeIntegration:true。7shell 应坚持最小权限与远端变更显式授权。
